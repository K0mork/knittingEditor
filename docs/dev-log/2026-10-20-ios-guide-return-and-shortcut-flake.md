# 2026-10-20 — 使い方ページの戻るリンクを画面下端の帯より上で押し、ショートカットの送り直しを増やす

- 影響: iOS UIテストの断続的な1回目失敗2件への対処。アプリの動作は変えていない。
  - `testGuideNavigationReturnsToUsableEditor`（iPhone）：使い方ページを送る補助処理 `scrollWebViewUntilHittable` は、`isHittable` に加えて、要素の枠全体がWebViewの中にあり、下端がWebViewの下端から34pt（ホームインジケータの帯）より上に来るまで送る。押し直す前も同じ確認を通る。必要な送りが1回増えることがあるため、送りの上限を12回から14回にした。`testGuideExternalLinkShowsNoPreview` も同じ補助処理を使う。
  - `KeyboardCommandUITests` の `typeShortcut`（iPad）：ショートカットを送る回数を4回から8回に、1回の待ちを約11.25秒から8秒にした（合計最大64秒）。⌘O・⌘N・⌘S・⌘Z などを使う同じクラスのテストすべてに効く。
- 主なファイル: `ios/UITests/KnittingEditorUITests/KnittingEditorUITests.swift`、`ios/UITests/KnittingEditorUITests/KeyboardCommandUITests.swift`
- テスト: 上の2つの補助処理を更新。テストケースの追加・削除は無く、PRスモークの選択は変えていない。
- 原因: main `e7f0601` の Full iOS validation（run 39399989983）で、全ジョブ成功のまま2件が1回目に失敗し、再試行で成功した。PR #302 で残すようにした xcresult（画面写真・要素ツリー・合成したイベント・録画・Simulator のシステムログ）で調べた。
  - iPhone 17 `:91`（使い方から編集画面へ戻れない）→ `:96`（戻った後の盤面が無い）：末尾の「編集画面へ戻る」を出すため上スワイプを10回した後、リンクの枠は y=864・高さ19 で、画面（高さ874）の下端からはみ出していたが、`isHittable` が true になったため送りを止めた。XCUITest は (24, 873)＝画面の最下端から1ptの、ホームインジケータの帯を押し、効かなかった。押し直しも、送り直さずに同じ位置を押した。録画の最後のフレームでも、リンクのボタンは画面下端で切れていた。テストの作りの問題で、アプリの不具合ではない。#95（画面外の座標を押した）と同じ系統。
  - iPad (A16) `KeyboardCommandUITests.swift:114`（⌘Oで復元の選択画面が出ない）：準備完了の直後から ⌘O を約11.7秒おきに4回送ったが、4回とも効かなかった。Simulator のシステムログでは、キーはアプリのウィンドウに届いたが、UIKit はメニューのショートカットとして扱わず、文字入力の側に回していた。アプリの `open:` からページへの復元の指示は一度も出ていない。再試行でも1回目の ⌘O は同じ形で効かず、2回目で効いた。効かなかった回は2つのキーイベントの間隔が約73〜130ms、効いた回は約7〜17msだった。他のテストで最初の ⌘N が効かない件も同じ形だった。直近24回の Full iOS validation では、このテストは1回目で通った回も24〜79秒かかっており、ほぼ毎回 ⌘O が1〜3回効いていなかった。手元（KE verify iPad、iOS 27.0）で診断用のログを一時的に足して3回実行すると、3回とも最初の ⌘O で `open:` から選択画面まで動いた（ログは戻し、コミットしていない）。CI の Simulator で合成した ⌘＋キーがショートカットとして扱われないことがある、という判断。実機のハードウェアキーボードで最初の ⌘O が効くかは未確認で、#303 で確かめる。
- 検証: 手元で `git diff --check`、`node scripts/check-pr-smoke-ui-tests.mjs`、`xcodegen generate --spec ios/project.yml`、`xcodebuild build-for-testing`（KE verify iPad、Xcode 27.1）を実行して成功した。UIテストのビルドで出た警告は既存の1件（`:1681`）だけ。手元の Simulator では、KE verify iPad で `xcodebuild test-without-building -only-testing:knittingEditorUITests/KeyboardCommandUITests -only-testing:…/testGuideNavigationReturnsToUsableEditor -only-testing:…/testGuideExternalLinkShowsNoPreview -test-iterations 2` を実行した。`testFileAndHelpShortcutsOpenEditorActions` の1回目（34秒）と `testRestoreShortcutOpensBackupPicker` の2回（20秒・16秒）は成功した。一方で、アプリの起動に約595秒、「決定」のタップに約948秒かかるなど、変更していない操作が止まり、Undo/Redo の2件が失敗した（`:168`・`:213`・`:261`）。`testGuideExternalLinkShowsNoPreview` は成功したが4039秒かかった。Simulator を起動し直して流し直しても、最初のテストで約16分止まった。このとき Mac のロードアベレージは約300で、手元の結果は今回の変更の確認に使えないと判断し、実行を止めた。KE verify iPhone では実行していない。両端末の確認は CI に任せた。ブランチの `ios-full.yml`（run 39418940993、`1f7bd6b`、`workflow_dispatch`）は全ジョブ成功した。`ios_full` は iPhone 17・iPad (A16) とも、どのテストにも再試行が無かった。所要時間は次のとおり。`testGuideNavigationReturnsToUsableEditor` は iPhone 91秒・iPad 69秒、`testGuideExternalLinkShowsNoPreview` は iPhone 78秒・iPad 52秒。iPad の `KeyboardCommandUITests` は、`testRestoreShortcutOpensBackupPicker` が47秒、`testFileAndHelpShortcutsOpenEditorActions` が109秒（直近25回は46〜147秒）、Undo/Redo の2件が74秒・51秒で、いずれも上限150秒に収まった。同じ run の `app_update (iPad (A16))` では、`testSeedDocumentForAppUpdateProbe` が1回目に `:1708`（「編み図」でパネルが開かない）で失敗し、再試行で成功した。#44 に記録済みの症状で、今回変えた補助処理は通らない。PR の CI の結果は PR に記録する。
- デプロイ影響: なし。iOSのUIテストだけで、Pagesの配信物は変わらない。
