# 2026-11-11 — iOS版の実機確認の標準手順を決める

- 影響: iOS版の版ごとの実機確認を、提出前・公開前・公開後の3つの時期に分け、それぞれの手順を`ios/docs/DEVICE_TESTING.md`に決めた。提出前は、新しいスクリプト`ios/scripts/run-device-ui-tests.sh`が、端末のアプリを削除してから開発ビルドで`ios/UITests/device-ui-tests.txt`の14件のUIテストを流し、終わると入れ直してテストが作った編み図を消す。機種とOSの版、結果、画面写真は出力先に残す。公開前はTestFlightの版をiPhoneの機内モードで6つの操作だけ確かめ、公開後は製品ページと版だけを確かめる。`needs-device`のIssueは、直した版の提出前に確かめる。`ios/docs/RELEASE_RUNBOOK.md`の手順5・8・9、`ios/docs/REAL_DEVICE_RELEASE_CHECKLIST.md`、`AGENTS.md`、`ios/AGENTS.md`、`ios/DEVELOPMENT.md`は、この文書を参照するようにした。`scripts/check-pr-smoke-ui-tests.mjs`は実機の一覧も検査する。
- 主なファイル: `ios/docs/DEVICE_TESTING.md`、`ios/scripts/run-device-ui-tests.sh`、`ios/UITests/device-ui-tests.txt`、`scripts/check-pr-smoke-ui-tests.mjs`、`ios/docs/RELEASE_RUNBOOK.md`
- テスト: `scripts/check-pr-smoke-ui-tests.test.mjs`に、エラーに一覧の名前が出ることと、実機の一覧の検査を足した。
- 検証: `node scripts/check-pr-smoke-ui-tests.mjs`（PRスモーク11件、実機14件）、`npm test`、`ios/scripts/check-app-store-docs.sh`、`sh -n ios/scripts/run-device-ui-tests.sh`、`git diff --check`が成功した。スクリプトは、引数が無いとき、ペアリングしていない端末、ケーブルでつながっていない端末で、ビルドの前に止まることを確かめた。iPad Air 第5世代（iPadOS 27.2、有線）でこのブランチのスクリプトを実行し、14件すべてが1回目で成功して、アプリの入れ直しまで約10分で終わった。その前の実行では、アプリがウインドウで開く設定だったため`testPrimaryControlsRemainUsableInPortraitAndLandscape`が横向きの配置にならず失敗したので、手順にiPadをフルスクリーンにしておく前提を足した。また、テストが失敗すると端末の診断情報を数分かけて集めたので、`-collect-test-diagnostics never`で集めないようにした。iPhoneでは実行していない。
- デプロイ影響: なし。文書とスクリプトだけで、Pages・アプリの中身は変わらない。
