# 2026-10-09 — 復元できないファイルの理由を日本語で出し、「安全上限」を「上限」にする

- 影響: 壊れた`.knit`や`.knit`以外のファイルを復元しようとすると、解凍ライブラリ（fflate）やブラウザの英語のエラー（`invalid gzip data`、JSONの読み取りのエラーなど）がそのまま画面に出ていたのを直した。iPhone 17（iOS 27.0）の実機で、でたらめなデータの`.knit`をAirDropで受け取って開いたときに英語の表示が出ることを確かめた。解凍とJSONの読み取りに失敗したときは「バックアップを読み込めませんでした。ファイルが壊れているか、.knitのバックアップではありません」と出す。中身がオブジェクトでないJSON（`null`や数値など）は「対応していないバックアップ形式です」、盤面のデータのbase64が壊れているときは「盤面データが破損しています」と出す。大きさの上限を超えたときの理由（「バックアップファイルが大きすぎます」「解凍後のバックアップが大きすぎます」）は今までどおり出す。あわせて、画面に出る文言の「安全上限」を「上限」に変えた（PNGの「一辺が上限16384pxを超えます」「画像のメモリ使用量が上限を超えます」、バックアップの「件数が上限を超えています」「記号数が上限を超えています」）。上限の値は変えていない。Web版とiOS版の両方に入る。
- 主なファイル: `packages/editor-core/storage/database.ts`、`packages/editor-core/export/exporters.ts`
- テスト: `storage/database.test.ts`に、gzipでないファイル・gzipの中身がJSONでないファイルで日本語の理由になること、オブジェクトでないJSONを拒むこと、盤面のbase64が壊れているときの理由、解凍後の大きさが上限を超えたときに理由が変わらないことを確かめるテストを足した。上限を超えるデータは、1MiBのゼロを圧縮したgzipを上限を超える数だけつなげて作り、テストを1秒以内に収めた。件数の上限のテストは新しい文言に合わせた。
- 検証: `npm run typecheck`、`npm test`（37ファイル259件）、`npm run build`、`npm run check:dist`、iOS Webの型検査（`ios/Web`で`tsc -p tsconfig.app.json --noEmit`）とテスト（`vitest run --config vite.config.ts`、34件）、`npm run test:e2e`（chromium-mobile、webkit-mobile、chromium-desktopで158件成功、既存の4件はスキップ）を実行し、すべて成功した。`dist/CNAME`が`knittingeditor.com`のままであることを確かめた。手元のNode.jsは26.8.1で、指定の24ではない。この修正を入れたアプリをiPhone 17（iOS 27.0）に入れ、でたらめなデータの`.knit`を開くと日本語の理由が出ること、1000×1000の盤面で1セルの画素数を最大にしてPNGを保存しようとすると「一辺が上限16384pxを超えます。PDF保存をおすすめします。」と出ることを、利用者が実機で確かめた。XcodeGen、Simulatorのテスト、アプリのArchiveはPRのCIで確かめる（Swiftとビルド設定は変えていない）。
- デプロイ影響: Pagesへ配信される。配信後に`https://knittingeditor.com/`で、`.knit`以外のファイルを「復元」で選ぶと日本語の理由が出ることを確かめる。
