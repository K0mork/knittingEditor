# 2026-10-08 — Web版にContent-Security-Policyを設定する

- 影響: Web版の本番ビルドが出力するすべてのHTML（編集画面、`/guide/`、`/support/`、`/third-party-notices/`、今後`public/`へ足すページ）に、`<meta charset>`の直後へ`<meta http-equiv="Content-Security-Policy">`を入れる。GitHub Pagesはレスポンスヘッダーを付けられないためmetaで指定する。ポリシーは`default-src 'self'`を基本に、`script-src`は`'self'`と`https://www.googletagmanager.com`（gtag.js）、`connect-src`と`img-src`はGoogleのCSPガイドにあるGA4（Googleシグナルなし）の送信先、`img-src`に`data:`と`blob:`、`worker-src 'self'`（PDFのモジュールワーカー）、`object-src 'none'`、`base-uri 'self'`、`form-action 'self'`。利用者の判断で、`style-src`は`'self' 'unsafe-inline'`とし、記号SVGの`style`属性と使い方などのページの`<style>`要素はそのまま使う。スクリプトにはインラインを許さず、インラインのスクリプトや`on*`属性がHTMLにあるとビルドを止める（ld+jsonは対象外）。metaでは効かない`frame-ancestors`は入れていない。利用者の判断で、CSPは本番ビルドにだけ入れ、開発サーバー（`npm run dev`）には入れない。CSP違反は本番ビルドで動くE2Eが検出する。利用者の判断で、iOS版には入れず、入れるかは#135で判断する。
- 主なファイル: `scripts/content-security-policy.mjs`、`scripts/content-security-policy.d.mts`、`vite.config.ts`、`scripts/check-dist.mjs`、`tests/e2e/fixtures.ts`、`tests/e2e/csp.spec.ts`、`ios/docs/WEB_SYNC.md`
- テスト: `scripts/content-security-policy.test.mjs`（ポリシーの内容、インラインのスクリプトでビルドを止めること、metaの位置、付け忘れ・書き換えの検出）を追加した。`npm run check:dist`が`dist/`のすべてのHTMLのポリシーを検査する。E2Eの全テストが`tests/e2e/fixtures.ts`の`test`を使うようにし、`securitypolicyviolation`イベントとブラウザのCSPエラーを集めて、テストの終わりに違反が1件も無いことを確かめる。これにより編集、PNG・PDF書き出し、バックアップ、復元、使い方・サポート・ライセンスのページの表示で違反が出ないことをChromiumとWebKitで確かめている。`tests/e2e/csp.spec.ts`で、各ページにポリシーが1つだけあり`<style>`が効くこと、記号SVGが枠いっぱいに表示されること、注入したインラインスクリプトと未許可の送信先が止められて違反として検出されること、gtag.jsの読み込みとGA4の送信先への送信が止められないこと（Googleへは送らず、Playwrightで応答を差し替える）を確かめる。既存のE2Eのうち、PNGをdata: URLの`fetch`で読む処理は`connect-src`に止められるので、Blobの直接生成に替えた。
- 検証: `npm run typecheck`、`npm test`（35ファイル、228件成功）、`npm run build`、`npm run check:dist`、`npm run test:e2e`（chromium-mobile・webkit-mobile・chromium-desktopで140件成功、iPhone Safari専用の4件は設計どおりスキップ）がすべて通った。共通コードは変えていないが、iOS Webの`tsc -p tsconfig.app.json --noEmit`と`vitest run --config vite.config.ts`も通った。ルートの`vite.config.ts`を変えたのでPRのCIでiOSの検査も走る。Simulatorの全テストなどiOSのほかの検査はPRのCIに任せた。
- デプロイ影響: Pagesへ配信される。配信後に、`https://knittingeditor.com/`をブラウザで開いて編集・PNG/PDF書き出し・バックアップ・復元・使い方ページの表示でコンソールにCSP違反が出ないこと、GA4のRealtimeでイベントが引き続き届くことを確かめる（件数は記録しない）。
- PRのCIで直したこと: CodeQLの「Bad HTML filtering regexp」の指摘で、インラインのスクリプトを探す正規表現が`</script >`のような終了タグに一致しなかったので、終了タグの空白や属性も受け付けるようにした。`scripts/content-security-policy.test.mjs`に`</script >`と大文字・改行入りの終了タグの例を足した。直したあと`npm run typecheck`、`npm test`（35ファイル、228件成功）、`npm run build`、`npm run check:dist`、`npm run test:e2e`（140件成功、4件は設計どおりスキップ）を再実行して通った。
- #133の後の取り込み: #133（プライバシーポリシー`/privacy/`）がmainへ入ったので、`origin/main`（2dd2920）をマージで取り込んだ。衝突は`ios/docs/WEB_SYNC.md`の差分表だけで、`index.html`・`public/guide/`の行は#133の記述、`vite.config.ts`の行はこのPRの記述を残した。`/privacy/`のCSPのmetaはほかのページと同じくビルド時に入り（ソースのHTMLには書かない）、`npm run check:dist`の検査対象にもなる。`tests/e2e/csp.spec.ts`の対象ページに`/privacy/`を足した。#133が足した`/privacy/`の表示と、「編み図」パネル・使い方・サポートからのリンクのE2Eも、共通のフィクスチャでCSP違反を検査する。取り込み後に`npm run typecheck`、`npm test`（35ファイル、229件成功）、`npm run build`、`npm run check:dist`、`npm run test:e2e`（149件成功、iPhone Safari専用の4件は設計どおりスキップ）、iOS Webの`tsc -p tsconfig.app.json --noEmit`と`vitest run --config vite.config.ts`を実行し、すべて通った。
