# 2026-10-08 — Web版にContent-Security-Policyを設定する

- 影響: Web版の本番ビルドが出力するすべてのHTML（編集画面、`/guide/`、`/support/`、`/third-party-notices/`、今後`public/`へ足すページ）に、`<meta charset>`の直後へ`<meta http-equiv="Content-Security-Policy">`を入れる。GitHub Pagesはレスポンスヘッダーを付けられないためmetaで指定する。ポリシーは`default-src 'self'`を基本に、`script-src`は`'self'`と`https://www.googletagmanager.com`（gtag.js）、`connect-src`と`img-src`はGoogleのCSPガイドにあるGA4（Googleシグナルなし）の送信先、`img-src`に`data:`と`blob:`、`worker-src 'self'`（PDFのモジュールワーカー）、`object-src 'none'`、`base-uri 'self'`、`form-action 'self'`。`style-src`は`'self'`と、各ページの`<style>`要素のSHA-256ハッシュだけを許し、`'unsafe-inline'`は使わない。ハッシュはビルド時に計算するので、ページのCSSを直しても手で更新する必要はない。インラインのスクリプト・`style`属性・`on*`属性がHTMLにあるとビルドを止める。metaでは効かない`frame-ancestors`は入れていない。開発サーバーにはReactの更新用インラインスクリプトや`<style>`によるCSSの差し込みがあるため、CSPは本番ビルドにだけ入れる。記号ピッカーと記号ボタンのSVG（`dangerouslySetInnerHTML`で入れる）は`style="width:100%;height:100%"`を`width="100%" height="100%"`属性に替えた。CSSOMで指定するReactの`style`プロパティはCSPの対象外なので変えていない。iOS版にはCSPを入れない（`ios/docs/WEB_SYNC.md`の`vite.config.ts`の行に理由を記載）。
- 主なファイル: `scripts/content-security-policy.mjs`、`scripts/content-security-policy.d.mts`、`vite.config.ts`、`scripts/check-dist.mjs`、`packages/editor-core/stitches/glyphs.ts`、`tests/e2e/fixtures.ts`、`tests/e2e/csp.spec.ts`、`ios/docs/WEB_SYNC.md`
- テスト: `scripts/content-security-policy.test.mjs`（ポリシーの内容、`<style>`のハッシュ、インラインのコードでビルドを止めること、metaの位置と付け忘れ・古いハッシュの検出）、`packages/editor-core/stitches/glyphs.test.ts`（記号SVGに`style`属性が無いこと）を追加した。E2Eの全テストが`tests/e2e/fixtures.ts`の`test`を使うようにし、`securitypolicyviolation`イベントとブラウザのCSPエラーを集めて、テストの終わりに違反が1件も無いことを確かめる。これにより編集、PNG・PDF書き出し、バックアップ、復元、使い方・サポート・ライセンスのページの表示で違反が出ないことをChromiumとWebKitで確かめている。`tests/e2e/csp.spec.ts`で、各ページにポリシーが1つだけあり`<style>`が効くこと、記号SVGが枠いっぱいに表示されること、注入したインラインスクリプトと未許可の送信先が止められて違反として検出されること、gtag.jsの読み込みとGA4の送信先への送信が止められないこと（Googleへは送らず、Playwrightで応答を差し替える）を確かめる。既存のE2Eのうち、PNGをdata: URLの`fetch`で読む処理と`page.addStyleTag`はCSPに止められるので、Blobの直接生成とCSSOMに替えた。
- 検証: `npm run typecheck`、`npm test`（35ファイル、230件成功）、`npm run build`、`npm run check:dist`、`npm run test:e2e`（chromium-mobile・webkit-mobile・chromium-desktopで140件成功、iPhone Safari専用の4件は設計どおりスキップ）がすべて通った。iOS Webの`tsc -p tsconfig.app.json --noEmit`と`vitest run --config vite.config.ts`も通った。検出の仕組みが働くことは、記号SVGを一時的に`style`属性へ戻して`tests/e2e/csp.spec.ts`を走らせ、3プロジェクトとも`style-src`の違反で失敗することで確かめた。`vite preview`で開いた本番ビルドで、記号ピッカーを開いた画面を`width`・`height`属性の版と、旧来と同じ指定（CSSOMで`width:100%;height:100%`）の版で撮り比べ、Chromium（デスクトップ・Pixel 7相当）とWebKit（iPhone 14相当）で画素が完全に一致することを確かめた。PNG・PDFは`drawGlyph`・`glyphPdfCommands`で描き、SVG文字列を使わないので出力は変わらない。WebKitでは`page.screenshot()`のときにPlaywright自身が`<style>`を差し込んで違反として出るが、アプリの違反ではない（`tests/e2e/fixtures.ts`に記載）。Simulatorの全テストなどiOSのほかの検査はPRのCIに任せた。
- デプロイ影響: Pagesへ配信される。配信後に、`https://knittingeditor.com/`をブラウザで開いて編集・PNG/PDF書き出し・バックアップ・復元・使い方ページの表示でコンソールにCSP違反が出ないこと、GA4のRealtimeでイベントが引き続き届くことを確かめる（件数は記録しない）。
