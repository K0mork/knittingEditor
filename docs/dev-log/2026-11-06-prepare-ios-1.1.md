# 2026-11-06 — iOS版1.1の提出に向けて、版を上げ、審査メモと新機能の文を用意する

- 影響: v1.0（`ios-v1.0-build1`）のあとに`main`へ入った変更で、iOS版1.1を提出する準備をした。`ios/project.yml`の`MARKETING_VERSION`を`1.1`にし、XcodeGenで`ios/knittingEditor.xcodeproj`を作り直した（変わったのは版の2行だけ）。ビルド番号（`CURRENT_PROJECT_VERSION`）は`1`のままで、アップロードのときにXcodeが付ける。「使い方」の末尾の版の表示は`Info.plist`から読むので、1.1になる。提出手順の10に従い、v1.0から増えた・変わった操作を審査メモの英語・日本語の両方に「New in version 1.1」「バージョン1.1の変更点」として足した（範囲選択の帯の「消去」「保存」、「やめる」まで続く貼付、さらに大きな文字、iCloud Driveのダウンロード失敗の案内）。App Store Connectの「このバージョンの新機能」の文を`APP_STORE_METADATA.md`に新しい節として置いた（利用者が文案を確認した。下のdeleteキーの文は事実と違ったので外した）。審査メモは4000文字までなので、`ios/scripts/check-app-store-docs.sh`が転記する範囲（「## English」から最後まで）の文字数を数え、超えたら失敗するようにした。今の審査メモは上限に収まっている。手順書の手順5の「`MARKETING_VERSION`は`1.0`のまま」を提出する版の番号に直し、手順10に、文字数の確認、新機能の文の置き場所、版を上げる作業を足した。
- 範囲を選んでいるときのdeleteキー（#393）: Web版ではDelete・Backspaceで選んだ範囲を消せるので、iPadのハードウェアキーボードでも効くなら使い方と審査メモに書くつもりで確かめた。`KeyboardCommandUITests`に`typeKey(XCUIKeyboardKey.delete)`で消すUIテストを仮に足し、KE verify iPad（iOS 27.2）で実行したところ、7段×6目の範囲を選んだ状態で記号が1個のまま消えず失敗した。iPadのアプリではdeleteキーがページの`keydown`に届かないとみられる。効かない操作は書かず、仮のテストも消した。iOSの使い方は、もともとdeleteキーに触れていない。
- 主なファイル: `ios/project.yml`、`ios/knittingEditor.xcodeproj/project.pbxproj`、`ios/docs/APP_REVIEW_NOTES.md`、`ios/docs/APP_STORE_METADATA.md`、`ios/docs/RELEASE_RUNBOOK.md`、`ios/scripts/check-app-store-docs.sh`、`scripts/app-privacy-docs.test.mjs`
- テスト: `scripts/app-privacy-docs.test.mjs`に、審査メモの転記範囲が4000文字ちょうどなら通り4001文字なら失敗するテストと、「## English」の節が無いと失敗するテストを足した。
- 検証: `cd ios && xcodegen generate`（差分は`MARKETING_VERSION`の2行だけ）、`xcodebuild build -project ios/knittingEditor.xcodeproj -scheme knittingEditor -configuration Debug -destination 'platform=iOS Simulator,id=<KE verify iPad>'`（成功。ビルドした`Info.plist`の`CFBundleShortVersionString`が`1.1`）、`sh ios/scripts/check-app-store-docs.sh`（成功）、審査メモに200文字足した写しで検査が`4119/4000`で失敗することを手で確かめた、`npx vitest run scripts/app-privacy-docs.test.mjs`（24件成功）、`npx vitest run scripts/guide-content.test.mjs`（成功）、`npm test`（82ファイル・1062件成功）、`git diff --check`（成功）。deleteキーの仮のUIテストは上のとおり失敗し、消した。WebとiOSのアプリのコードは変えていないので、`npm run build`・`npm run test:e2e`・iOS Webのテストは実行していない。iOSのテスト一式はPRとマージ後のFull iOS validationに任せる。
- デプロイ影響: Pagesの配信内容は変わらない。マージ後にArchiveするiOSアプリの版が1.1になる。提出は手順書の5〜9のとおり、マージ後の`main`のコミットで`ci-gate`とFull iOS validationが成功したことを確かめてから、利用者が手元のXcodeでArchiveしてアップロードし、App Store Connectで版1.1を作って「このバージョンの新機能」と審査メモを転記し、手動公開で提出する。アップロードしたビルドには`ios-v1.1-build<番号>`のタグを付ける。審査と並行してTestFlightで提出ビルドを実機で確かめる。
