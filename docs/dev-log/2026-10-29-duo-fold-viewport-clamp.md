# 2026-10-29 — 縮小した盤面を狭い画面へ移しても、隠れた側を空きで見せる

- 影響: 画面の大きさが変わったとき（iPhone Duoの開閉、回転、可変幅ウィンドウ）、盤面は編み始め（右下）とキャンバス右下の距離を保つ。縮小して右や下に空きを残した盤面では、狭くなった画面でも同じ長さの空きが残っていた。そのため、全体が画面に収まる盤面でも左や上が画面の外に押し出されていた（#367）。狭くなった向きに限り、盤面の左や上が帯の外側の余白（8px）より外に出たら、右や下の空きを使って、狭くなった分までその側を見せる。広がった向きと、大きさが変わらない向きは動かさない。キーボードの開閉、選択・貼付の帯、パネルで表示位置が変わらない今の動きはそのまま。
- 原因の確認: 一時的に、画面の大きさと表示位置の移り変わりを画面に書き出すビルドを作り、Simulator「iPhone Duo」（iOS 27.1、Xcode 27.1のDebugビルド）で調べた。
  - Issueの手順（新しい編み図、名称の変更、編み図の切り替え、ダークモード）では、横向き・縦向きのどちらから閉じても、大きさの変化は1回か2回で届き、盤面は右下に揃った。
  - 32目の盤面を内側の縦向きで2本指で縮小し、右に214pt、下に228ptの空きを残してから閉じた。外側の画面でも右の空きは214ptのまま残った。計算では、外側の縦向き（canvas 382×458）なら左の約15目が画面の外に出る。Issueの観察（左の14目ほどが外、右に約4割の空き）と合う。修正後に同じ手順で閉じると、下の空きは8ptまで詰まり、左の目もすべて見えた。
  - 拡大・縮小は指の中心を基準にし、範囲へ戻す処理は端のマスが画面の中央に来るまで許す。このため、2本指の操作だけでは空きは埋まらない。Issueの「閉じる前の大きさで計算している」という見立ては当たっていなかった。
- 主なファイル: `packages/editor-core/canvas/BoardCanvas.tsx`
- テスト:
  - `packages/editor-core/canvas/BoardCanvas.test.ts`: `resizeViewport`に盤面の大きさを渡すよう変えた。開閉をまたいで右下の位置が保たれる確認は、編み始めを右下から8pxに置いた位置で行うようにした。Duoを閉じた場合（32目・縮小・空きあり）に左を見せること、全体が見える盤面では空きを保つこと、広がった向き（キーボードが閉じたとき）では横の位置を変えないことを足した。
  - `tests/e2e/canvas-pointer-and-view.spec.ts`: 669×869で32目の盤面を縮小し、466×678へ狭めたとき、盤面の左端が帯より外に出ないことを確かめるテストを足した。直す前のコードでは失敗することを確かめた（chromium-mobile）。
