# 2026-10-09 — iOS版で名前の入力欄を開いたらすぐキーボードを出す

- 影響: iOS版で「編み図」→「新しい編み図」を押すと、名前を入力するアプリ内ダイアログは出るがキーボードが出ず、入力欄をもう一度タップしないと名前を打てなかったのを直した（#148）。ダイアログは入力欄へのフォーカスを次のフレーム（`useModalFocus`の`requestAnimationFrame`）で当てていたため、`WKWebView`がタップによる入力とみなさず、キーボードを出していなかった。入力欄が画面に反映された直後（`useLayoutEffect`）にフォーカスし、初期値を選択するようにした。「新しい編み図」などのボタンはタップの処理の中でダイアログを開くので、フォーカスも同じタップの処理の中に収まる。名前の変更、ブロック名の入力、段・列の位置の入力も同じダイアログを使うので、同じく直る。iPhoneの横向きでは、キーボードがダイアログの「キャンセル」「決定」を覆うことが分かった。直す前から起きていたので、別の不具合として#151にした。iOS版だけの変更で、Web版は`window.prompt`を使うので変わらない。
- 主なファイル: `ios/Web/src/AppDialog.tsx`、`ios/UITests/KnittingEditorUITests/KnittingEditorUITests.swift`
- テスト: XCUITestの`testNewDocumentDialogFocusesNameInputWithoutTapping`を足した（「新しい編み図」を押した直後、入力欄をタップしなくても入力欄にキーボードのフォーカスが入り、iPhoneでは画面のキーボードが出ること。CIのiPad Simulatorはハードウェアキーボード接続状態で画面のキーボードを出さないことがあるので、iPadではフォーカスだけを確かめる）。実機は端末の向きのまま始まり、横向きではキーボードがボタンを覆う（#151）ので、このテストと`testDocumentDialogRemainsUsableAfterFocusingInput`は縦向きにしてから始めるようにした。
- 検証: iOS Webの型検査（`ios/Web`で`tsc -p tsconfig.app.json --noEmit`）とテスト（`vitest run --config vite.config.ts`、34件）を実行し、成功した。`xcodegen generate`のあと、iPhone 16のSimulatorで、足したテストが直す前は失敗し、直したあとは成功することを確かめた。iPhone 17（iOS 27.0）の実機で、足したテスト、`testDocumentDialogRemainsUsableAfterFocusingInput`、`testPromptDialogIgnoresBackgroundTaps`、`testDocumentSwitchAutosavesEachDocument`が成功した。実機で横向きにしてキーボードを出すと、直す前も直したあとも「キャンセル」「決定」が押せなかった（#151）。利用者が実機で、「新しい編み図」・名前の変更・段の挿入の位置の入力で、すぐキーボードが出ることを確かめた。Web版と共通コード（`packages/`）は変えていないので、`npm run build`・`npm run check:dist`・`npm run test:e2e`は実行していない。UIテストを含むSimulatorのテスト全体、更新復元、アプリのArchiveはPRのCIで確かめる。
- デプロイ影響: なし（iOSのみの変更で、Pagesは再配信されない）。
