# 2026-11-19 — Webアプリマニフェストと端末内データの永続化をAndroid Chromeへ入れる

- 影響: Web版にWebアプリマニフェスト（`public/manifest.webmanifest`）を置き、`index.html`から読み込む（#486）。名前「棒針編み図エディタ」、`start_url`と`scope`は`/`、`display: standalone`、テーマ色は`index.html`の`<meta name="theme-color">`（ライト）と同じ`#3d7a4a`、背景色はページの地の色`#f3f0e8`、`lang: ja`。アイコンは既存の`icon-192.png`（`purpose: any`）に、新しく作った512pxの`icon-512.png`（`any`）と、アプリアイコン（`ios/App/AppIcon.icon`）の層を中央80%へ縮めて背景色で囲んだ`icon-512-maskable.png`（`maskable`）を加えた。AndroidのChromeでホーム画面に追加してアプリのように開けるようにするためで、Service Worker（オフライン動作）はこの変更に入れない。`scripts/check-dist.mjs`と`scripts/check-live-site.mjs`（`smoke`）はmanifestと新しいアイコンを確かめる。iOS版（`ios/Web/`）の同梱ページにはmanifestも`persist()`も入れない。あわせて、Chromeが空き容量の足りないときに永続化していないサイトのIndexedDBを消すことがあるため、最初の編み図の保存が成功した後で`navigator.storage.persist()`を呼び、端末内データの永続化を求める。ページ読み込みにつき1回だけ、`navigator.storage`に対応していて既に永続化されていないときだけ呼ぶ。Firefoxは`persist()`で確認を出すので、この時機にした。拒否・未対応・失敗では何も表示せず、エラーも飲み込む。
- 主なファイル: `public/manifest.webmanifest`（新規）、`public/icon-512.png`（新規）、`public/icon-512-maskable.png`（新規）、`index.html`、`scripts/generate-web-icons.mjs`（512pxとmaskableの出力を追加）、`src/persistentStorage.ts`（新規）、`src/App.tsx`、`packages/editor-core/ui/useEditorController.ts`（保存成功の通知`onSaveSuccess`を省略可能な引数にする）、`scripts/content-security-policy.mjs`（`manifest-src 'self'`を明示）、`scripts/check-dist.mjs`（manifestの検査を`verifyWebAppManifest`として出し、mainは直接実行のときだけ動かす）、`scripts/check-live-site.mjs`、`docs/WEB_SYNC.md`
- テスト: `src/persistentStorage.test.ts`（新規）で、最初の保存の後に1回だけ求めること、既に永続化されていれば求めないこと、未対応では何もしないこと、拒否・失敗で何も表示せず投げないこと、保存が続いても1回だけであることを確かめる。`packages/editor-core/ui/useEditorController.test.tsx`で、保存が成功するたびに`onSaveSuccess`が呼ばれ、失敗のあとには呼ばれないことを確かめる。`src/App.persistence.test.tsx`（新規）で、`App`が保存成功の通知を`requestPersistentStorageOnce`へつなぐことを確かめる。`scripts/check-dist.test.mjs`（新規）で、リポジトリのmanifestが検査を通り、名前・色・`start_url`・`display`・アイコンの変更を検査が報告することを確かめる。`scripts/check-live-site.test.mjs`で、manifestが誤ったcontent-typeで返ったときとmaskableアイコンが404のときを報告することを確かめる。`scripts/content-security-policy.test.mjs`で`manifest-src 'self'`を確かめる。`tests/e2e/seo.spec.ts`で、`<link rel="manifest">`とmanifestのJSON（名前・`display`・テーマ色・3つのアイコン）と、アイコンの寸法を確かめる。
- 検証:
  - 512pxとmaskableのアイコンは、`ios/App/AppIcon.icon`の層SVG（`needles.svg`・`yarn.svg`）と背景色から、`rsvg-convert`（1024pxへ描画）と`magick`（背景色へ重ねて512pxへ縮小、maskableは層を409px＝80%へ縮小）で作った。この環境ではPlaywrightのChromium（`scripts/generate-web-icons.mjs`の経路）を起動できないためで、既存の`icon-192.png`を同じ手順で作り直して比べると、画素の差は0.3%程度（ラスタライザのアンチエイリアスの違い）だった。`scripts/generate-web-icons.mjs`にも512pxとmaskableの出力を加えたので、macOSでは既存のアイコンと同じ経路で作り直せる。
  - `npm run typecheck`成功。`npm test`は1202件中1201件成功、`packages/editor-core/model/thumbnail.test.ts`の性能のしきい値（250ms）だけ失敗した。単独実行では19件とも成功し、全体の再実行では成功するときもある、この環境の負荷によるもので、この変更は触れていない。`npm run build`成功（`dist verified: 3261.3 KiB`は`npm run check:dist`の結果）。`npm run check:dist`成功。`npx vitest run src/persistentStorage.test.ts src/App.persistence.test.ts packages/editor-core/ui/useEditorController.test.tsx scripts/check-dist.test.mjs scripts/check-live-site.test.mjs scripts/content-security-policy.test.mjs`（103件成功）成功。
  - `npx vite preview`で配信物を確かめ、`/manifest.webmanifest`は`application/manifest+json`、`/icon-512.png`と`/icon-512-maskable.png`は`image/png`で返ることを`curl`で確かめた。GitHub Pagesが`.webmanifest`を`application/manifest+json`で返すことは、Pages上のほかのサイト（`https://primer.github.io/design/manifest.webmanifest`）で同じことを確かめた。
  - 共通コード（`useEditorController.ts`）を変えたので、iOS Web単独の確認も行った。`ios/Web`で`../../node_modules/.bin/tsc -p tsconfig.app.json --noEmit`成功、`../../node_modules/.bin/vitest run --config vite.config.ts`（158件成功）成功。
  - Playwright E2E（`npm run test:e2e`）とiOS（Simulator・Xcode）の確認はこの環境で動かせないため、リーダーが実行する。
- デプロイ影響: あり（Pagesへ配信される）。配信後は`smoke`（`scripts/check-live-site.mjs`）が`/manifest.webmanifest`と2つの新しいアイコンを確かめる。Chrome DevToolsのApplication > Manifestでのインストール条件の確認、Android実機かエミュレーターでのホーム画面への追加と`navigator.storage.persisted()`の結果、iPhone・iPadのSafariで「ホーム画面に追加」の挙動とApp Storeアプリの案内とのかね合いは、この変更だけでは確かめられないので#486に残す。
