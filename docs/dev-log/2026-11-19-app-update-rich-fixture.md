# 2026-11-19 — iOSアプリ更新確認のfixtureに色・幅のある記号・点線・背景色・ブロック・2つ目の編み図を足す

- 影響: `app_update`ジョブ（`testSeedDocumentForAppUpdateProbe`・`testUpdatedAppRestoresSeedDocument`）が、更新前のアプリに保存した編み図のうち、これまで確かめられなかった内容（色・幅のある記号・点線・背景色・保存済みブロック・複数の編み図）も更新後に読めることを確かめるようにした（#446）。fixtureはUIで組み立てず、更新前アプリの起動時にDEBUG専用フック（`KNITTING_EDITOR_APP_UPDATE_FIXTURE=1`）でIndexedDBへ書き込む。理由は2つ。色・幅のある記号・点線・背景色をUIで置くと1操作に数十秒かかった実績（#441）から1テスト240秒の上限を超える恐れがあることと、記号の既定と違う色を選ぶ手段がUIの`<input type="color">`だけでXCUITestから確実に操作できないこと。書き込みは自動保存と同じレコード（`ChartDocument`・`PatternBlock`）を通るので、更新後のアプリが読む内容は利用者が保存した編み図と同じ形になる。fixtureの内容は`appUpdateFixture()`が1つの関数で作り、目印は2つ目の編み図名「アプリ更新復元fixture2」。更新後のテストは目印の有無でfixtureの版を区別し、前のリリースのタグ（今は`ios-v1.1-build1`）が保存する最小fixture（「アプリ更新復元fixture」に記号1個）も引き続き読める。新しいfixtureが`app_update`ジョブの更新前アプリで実際に保存されるのは、次のリリースのタグを付けたあと。あわせて、盤面の読み上げ（`BoardCanvas`の`aria-label`）にガイド線の本数「ガイド線N本。」を記号数のあとに足した。線を引いていない盤面では読み上げは変わらない。この読み上げはWeb版にも配信され、点線が残ったことをUIテストから確かめる手段になる。
