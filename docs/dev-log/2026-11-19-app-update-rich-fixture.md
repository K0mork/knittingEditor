# 2026-11-19 — iOSアプリ更新確認のfixtureに色・幅のある記号・点線・背景色・ブロック・2つ目の編み図を足す

- 影響: `app_update`ジョブ（`testSeedDocumentForAppUpdateProbe`・`testUpdatedAppRestoresSeedDocument`）が、更新前のアプリに保存した編み図のうち、これまで確かめられなかった内容（色・幅のある記号・点線・背景色・保存済みブロック・複数の編み図）も更新後に読めることを確かめるようにした（#446）。fixtureはUIで組み立てない。遅いランナーで1操作に数十秒かかった実績（#441）から1テストの上限（240秒）を超える恐れがあることと、既定と違う記号の色をUIの`<input type="color">`で選べずXCUITestから確実に操作できないため、起動時のDEBUG専用フック（`KNITTING_EDITOR_APP_UPDATE_FIXTURE=1`）で書き込む。書き込みは、利用者が編み図を作って保存するときと同じ保存の公開API（`createDocument`・`saveDocument`・`saveBlock`・`activeDocumentId`の設定）を通る。保存の記録を手作りしないので、本物の保存経路へ将来の項目が加わっても、更新後のアプリが読むのは利用者が保存した編み図と同じ形になる。既存文書があるときは何も書かないため、テストの再試行でも追記しない。Releaseにはこの経路が入らない。目印は2つ目の編み図名「アプリ更新復元fixture2」で、更新後のテストは目印の有無でfixtureの版を区別し、前のリリースのタグ（`ios-v1.1-build1`）が保存する最小fixture（記号1個）も引き続き読める。復元テストは色の道具を名前で探すが、道具列の色と記号の道具は`aria-haspopup="dialog"`を持つため、iOS 27.2のSimulatorのWebKitはこの道具を読み上げ上の種類`Button`ではなく`Other`として公開する。そのため記号の選択画面（`編み目記号を選ぶ`）と同じく、種類を問わず名前で照会する。あわせて、盤面の読み上げ（`BoardCanvas`の`aria-label`）にガイド線の本数「ガイド線N本。」を記号数のあとに足した。線の無い盤面では読み上げは変わらない。
- 主なファイル: `packages/editor-core/storage/appUpdateFixtureData.ts`（新規）、`ios/Web/src/debugAppUpdateSeed.ts`（新規）、`ios/Web/src/App.tsx`、`ios/Web/src/nativeEditorConfiguration.ts`、`ios/App/DebugEditorConfiguration.swift`、`ios/UITests/KnittingEditorUITests/KnittingEditorUITests.swift`、`packages/editor-core/canvas/BoardCanvas.tsx`、`ios/scripts/simulate-app-update.sh`（コメントのみ）、`ios/DEVELOPMENT.md`
- テスト: `appUpdateFixtureData.test.ts`（fixtureが表す内容: 文書2つの名前と地の色、リリース済み最小fixtureと同じ中央の記号、色付きセル・幅2目の記号・点線、目印の記号1個、`Board.createBlock`で作ったブロックを貼り付けて戻せること）。`debugAppUpdateSeed.test.ts`（保存のAPIを通って書かれた記録を`listDocuments`・`listBlocks`・`getSetting`で読めること、既存文書があるときは何も書かないこと）。`BoardCanvas.test.ts`（ガイド線の本数を含む`aria-label`、線が無いときは含まないこと）。`DebugEditorConfigurationTests.swift`（`KNITTING_EDITOR_APP_UPDATE_FIXTURE`が「1」のときだけ真偽値として注入すること）。`tests/e2e/guide-lines.spec.ts`（線を引いたあとの`aria-label`）。
