# 2026-10-09 — iPhoneの横向きで黒い帯を無くし、キーボードの上にダイアログを収める

- 影響: iPhoneを横向きにすると編集画面の左右に黒い帯が出ていたのを直した（#146）。SwiftUIで`WKWebView`を下の端だけセーフエリアの外へ広げていたので、左右も広げ（`.ignoresSafeArea(.container, edges: [.horizontal, .bottom])`）、iOS版のページに`viewport-fit=cover`を指定した。上の端はステータスバーの文字の色と合わせるため広げていない。地の色が画面の端まで塗られ、ヘッダー・道具の列・盤面・右の列の操作メニューは、`env(safe-area-inset-left/right)`の余白でDynamic Islandと角をよける（共通CSSの`--safe-left`・`--safe-right`。Web版は`viewport-fit=cover`を指定しないので0）。スクロールビューの自動の余白（`contentInsetAdjustmentBehavior`）も残すと、下の端の余白がCSSの余白と二重になって操作メニューが浮くため、`.never`にし、余白はCSSだけで付けるようにした。縦向きの配置は以前と同じで、操作メニューの地の色がホームインジケーターの部分まで続くようになった。アプリ内で開く使い方ページ（iOS版）と第三者ソフトウェアのライセンスのページも、`viewport-fit=cover`のうえで左右のセーフエリアの余白を付け、横向きで本文がDynamic Islandにかからないようにした。WebViewを端まで広げると、横向きの幅が734ptから852ptになり、760pt以上で使う広い画面向けの並び（操作メニューを右の列に縦に並べる）に切り替わってしまった。高さの低い画面では右の列に操作メニューが収まらず、文字サイズを最大にするとボタンが画面の外に出た。広い画面向けの並びは、横幅760px以上で高さ501px以上のときだけにし、iPhoneの横向きは以前と同じ並び（操作メニューを下に横一列）のまま、左右の端まで広がるようにした。あわせて、もとからあった不具合も直した。広い画面向けの並びで高さに余裕が無いと、右の列の操作メニューが収まらず、横にスクロールする道具の列のほうが押し縮められてボタンが上下で切れていた（本番のWeb版でも852×393で起きていた）。盤面の行を縮められるようにし（`minmax(0, 1fr)`）、操作メニューは収まらないときに列の中でスクロールするようにした。iPhoneの横向きでキーボードを出すと、名前の入力ダイアログの「キャンセル」「決定」がキーボードに隠れて押せなかったのも直した（#151）。実機ではキーボードが出るとWebViewがキーボードの上まで縮み、横向きでは高さが120pt前後になる。横向きで高さ500px以下ではダイアログを画面の上に寄せて詰め、高さ260px以下では入力欄と「キャンセル」「決定」を1行に並べた（`ios/Web/src/styles.css`）。
- 主なファイル: `ios/App/KnittingEditorApp.swift`、`ios/App/WebViewContainer.swift`、`ios/Web/index.html`、`ios/Web/src/styles.css`、`ios/Web/public/guide/index.html`、`packages/editor-core/styles/base.css`、`scripts/third-party-notices.mjs`、`ios/UITests/KnittingEditorUITests/KnittingEditorUITests.swift`
- テスト: XCUITestの`testPrimaryControlsRemainUsableInPortraitAndLandscape`に、横向きでWebViewが画面の幅いっぱいに広がること（左右に帯が無いこと）の確認を足した。直す前のSimulatorでは、WebViewの左右に59ptずつ帯があるとして失敗した。`testNameDialogButtonsStayAboveKeyboardInLandscape`を足した（横向きで名前の入力ダイアログを開いてキーボードを出しても、「キャンセル」「決定」が押せること。iPhoneではキーボードが出ることも確かめる）。このテストはSimulatorでは直す前でも成功したが、実機（iPhone 17 / iOS 27.0）では直す前に失敗し、直したあとは成功した。#148で足したテストのコメントは、横向きをこのテストで確かめることに合わせて直した。
- 検証: `npm run typecheck`、`npm test`（37ファイル259件）、`npm run build`、`npm run check:dist`、iOS Webの型検査（`ios/Web`で`tsc -p tsconfig.app.json --noEmit`）とテスト（`vitest run --config vite.config.ts`、34件）、`npm run test:e2e`（chromium-mobile、webkit-mobile、chromium-desktopで158件成功、既存の4件はスキップ）を実行し、すべて成功した。`dist/CNAME`が`knittingeditor.com`のままであることを確かめた。手元のNode.jsは26.8.1で、指定の24ではない。開発サーバーとブラウザで852×393を表示し、道具の列が切れないことを確かめた。iPhone 16のSimulatorで、縦向きの配置が直す前と同じであることと、横向き（左右どちら向きも）で地の色が端まで広がり、ボタンと段・目の番号がDynamic Islandをよけること、使い方ページの本文がDynamic Islandにかからないことをスクリーンショットで確かめた。iPhone 17の実機では、横向きのダイアログが1行に並んでキーボードの上に収まることをスクリーンショットで確かめた。`xcodegen generate`のあと、UIテスト全体（CIと同じく`testBackupExportSheetDismissesBackToEditor`を除く）をiPhone 16のSimulatorとiPhone 17（iOS 27.0）の実機で実行し、どちらも実行した19件がすべて成功した（iPad用・測定用など9件は既定どおりスキップ）。広い画面向けの並びに高さの条件を加える前は、Simulatorで文字サイズ最大の横向きのテスト（`testAccessibilityExtraExtraExtraLargeKeepsLandscapeHeaderInWindow`）が、右の列の「ブロック」「保存」が押せないとして失敗していた。Simulatorのテスト全体（iPad）、更新復元、アプリのArchiveはPRのCIで確かめる。
- デプロイ影響: Pagesへ配信される（共通CSSの、広い画面向けの並びに切り替える条件に高さを加えたことと、盤面の行と操作メニューの変更）。高さ500px以下の画面では、横幅が760px以上でも操作メニューが下に並ぶ。配信後に`https://knittingeditor.com/`を横幅760px以上・高さ400px前後と、横幅1280px・高さ720pxで開き、どちらも道具の列が切れず、操作メニューが押せることを確かめる。
