# 2026-10-09 — 「ファイル」アプリで.knitをタップしたらアプリで開いて復元する

- 影響: iOS版で、「ファイル」アプリの`.knit`をタップすると、このアプリが開いて編み図を復元するようにした（#149）。今までは「ファイル」アプリのプレビューが開くだけで、共有メニューから「棒針編み図」を選ぶ必要があった。`ios/App/Info.plist`の`LSSupportsOpeningDocumentsInPlace`を`true`にした。iPhone 16のSimulatorで、「このiPhone内」に置いた`.knit`をタップして比べると、`false`ではプレビューが開くだけで、`true`ではアプリが開いて「1件の編み図を復元しました」と出た（アプリを閉じているときと開いているときの両方）。種類の宣言に`public.content`を足すことや、ドキュメントブラウザへの作り替えは要らなかった。`true`にすると、タップした`.knit`は複製されず、利用者の原本のURLが届く。`WebViewModel.readIncomingBackup`で、読む間だけアクセス権を得て（`startAccessingSecurityScopedResource()`）、`NSFileCoordinator`で他のアプリやiCloudの書き込みと調整して読むようにした。iCloud Driveの原本は読む前にダウンロードを待つことがあるので、読み取りはメインスレッドの外で行う。原本へは書き戻さず、削除もしない（タップしたあとも原本が残ることをSimulatorで確かめた）。AirDropや共有メニューから受け取った`.knit`は今までどおり`Documents/Inbox`の複製で、読んだあとに消す。同じ`.knit`をタップするたびに「（復元）」の編み図が増えるのは、共有メニューから開いたときと同じで、利用者の判断でそのままにした。iOS版の使い方ページのバックアップの注記に、「ファイル」アプリでタップしても復元されることを足した。`LSSupportsOpeningDocumentsInPlace`を有効にすると、PRのCIのiPad（iOS 26.5 Simulator）で、⌘Nで新しい編み図のダイアログが出ない、⌘Oで復元の選択画面が出ないとして、キーボードの近道のUIテスト4件が再試行を含めて失敗した（直前の`main`では成功していた）。手元にiOS 26.5のSimulatorを入れて再現させ、組み上がったメニューを書き出して調べると、有効にしたときだけ、iPadOSが「ファイル」メニューの先頭に「開く…」（⌘O、`open:`）と「最近使った項目を開く」を足し、アプリの「新しい編み図…」「バックアップから復元…」のグループがまるごと消えていた。⌘Nの項目だけのグループは消えず、⌘Oの項目を含むグループは、置き場所を「保存」のグループに移しても、そのグループごと消えた。システムの「開く…」と同じ⌘Oの項目があると、その項目を含むグループが外れる。「開く…」は、`UIMainMenuSystem`の`documentPreference`を`.removed`にしても（起動時・起動後のどちらで設定しても）消えなかった。利用者の判断で、iPadの「ファイル」メニューは「新しい編み図…」（⌘N）、「開く…」（⌘O）、「最近使った項目を開く」の並びにし、復元の項目はアプリからは置かず、「開く…」を`AppDelegate`（`UIApplicationDelegateAdaptor`）の`open:`で受けて復元の選択画面を開くようにした。
- 主なファイル: `ios/App/Info.plist`、`ios/App/EditorCommands.swift`、`ios/App/KnittingEditorApp.swift`、`ios/App/WebViewContainer.swift`、`ios/Tests/KnittingEditorAppTests/LocalWebSchemeHandlerTests.swift`、`ios/Web/public/guide/index.html`、`ios/docs/NATIVE_BRIDGE.md`
- テスト: 単体テスト`testIncomingBackupIsReadWithoutChangingTheOriginal`（原本を変えずにバイト列を読めること）と`testIncomingBackupOverTheLimitIsRejected`（上限を超えるファイルを大きすぎるとして断ること）を足した。`testSystemOpenCommandFollowsRestoreAvailability`（iPadOSの「開く…」は、編集画面が復元を受け付けるときだけ選べること）を足した。既存の`KeyboardCommandUITests`の⌘Oのテストが、「開く…」から復元の選択画面が出ることを確かめる。「ファイル」アプリを動かすUIテストは、「ファイル」アプリの状態の復元や、Simulatorの「このiPhone内」へテストからファイルを置けないことのため安定しないので、調べるための一時的なテストとして手元でだけ使い、リポジトリには入れていない。
- 検証: `xcodegen generate`のあと、iPhone 16のSimulatorで単体テスト（`-only-testing:knittingEditorTests`、80件のうち79件成功、1件は既定どおりスキップ）を実行し、成功した。直したあと、iOS 26.5のiPad (A16)のSimulatorでも単体テスト（81件のうち80件成功、1件は既定どおりスキップ）と`KeyboardCommandUITests`（4件）を実行し、成功した。iOS Webの型検査（`ios/Web`で`tsc -p tsconfig.app.json --noEmit`）とテスト（`vitest run --config vite.config.ts`、34件）、`ios/scripts/check-app-store-docs.sh`を実行し、成功した。Simulatorでの「ファイル」アプリからの確認は上記のとおり。UIテスト全体、iPad、更新復元、アプリのArchiveはPRのCIで確かめる。キーボードの近道のテスト（`KeyboardCommandUITests`、4件）は、CIと同じiOS 26.5のiPad (A16)のSimulatorで、直す前は`LSSupportsOpeningDocumentsInPlace`が無効なら成功・有効なら失敗し、直したあとは4件とも成功した。手元のiPad（第10世代）のiOS 18.2のSimulatorでは、無効のままでも⌘Sを含むショートカットがアプリに届かず、比べられなかった（iOS 18.2でも、組み上がったメニューにはシステムの「開く…」（⌘O）があった）。**実機での確認はまだ行っていない。** Simulatorはアクセス権の制限が実機ほど厳しくないため、実機（iPhone）で「このiPhone内」とiCloud Driveの`.knit`をタップして復元できること、原本が残ること、AirDrop・共有メニューからの復元が変わらないことを確かめてからマージする。
- デプロイ影響: none（iOS版だけの変更で、Pagesへは配信されない）。
