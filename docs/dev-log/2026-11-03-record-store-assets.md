# 2026-11-03 — App Store Connectに登録したスクリーンショットとヘッダの画像を記録する

- 影響: App Store Connectへの登録で分かったことを提出資料に反映した（#353）。iPhoneの欄はmedium displayの大きさ（1179×2556または1206×2622）しか受け付けず、6.9インチ（1320×2868）の画像は登録できなかったので、6.9インチの5枚を縮小した6.3インチ（1206×2622）の5枚を足した。iPhone Duoの欄は外側・内側のどちらの大きさも縦横どちらの向きも受け付け、必須の表示が無く、最大10枚なので、片方の5枚（v1.0では外側）を登録することを書いた。iOS 27以降の製品ページのヘッダと検索結果に共通で使う16:9の画像（5244×2950、透過なし）と、それを作るHTMLを足し、見出し（「棒針の編み図を、iPhoneとiPadで。」）とオフラインや「無料」を前面に出さない理由を書いた。最初の版はApp Store Connectのプレビューで、iPhoneの縦の画面では見出しの左側が切れていたため、プレビューのスクリーンショット2枚（iPhoneの縦とiPhone Duoの既定の向き）から表示される範囲を読み取り、21:9と3:2の範囲（縦横比から計算）とあわせて、文字がすべての範囲に入るよう中央にまとめた構図に作り直した。範囲は目安で、iPadなどほかの端末と向きは確かめておらず、Appleのテンプレートの安全範囲も使っていない。そのことと範囲を`SCREENSHOTS.md`に書き、HTMLを`?safe`付きで開くと重ねて表示する。`ios/scripts/check-release-assets.sh`は6.3インチの5枚とヘッダの画像の大きさ、ヘッダの画像に透過が無いことを、`ios/scripts/check-app-store-docs.sh`はそれらのファイルが`SCREENSHOTS.md`に載っていることを検査するようにした。
- 主なファイル: `ios/docs/SCREENSHOTS.md`、`ios/docs/APP_STORE_METADATA.md`、`ios/docs/APP_STORE_CHECKLIST.md`、`ios/docs/RELEASE_RUNBOOK.md`、`ios/docs/screenshots/app-store-iphone-6.3-0*.png`、`ios/docs/screenshots/app-store-creative-universal.png`、`ios/design/app-store-creative/universal.html`、`ios/scripts/check-release-assets.sh`、`ios/scripts/check-app-store-docs.sh`
- テスト: `scripts/app-privacy-docs.test.mjs`の、`SCREENSHOTS.md`に提出用の画像が載っていないと失敗することを確かめるテストを、iPhone Duoの1枚に加えて6.3インチの1枚とヘッダの画像でも行うようにした。
- 検証: `bash ios/scripts/check-release-assets.sh <b0a7f26のアーカイブ内の.app>`（成功）。ヘッダの画像を一時的に透過ありにすると同じ検査が失敗し、戻すと成功することを確かめた。`bash ios/scripts/check-app-store-docs.sh`（成功）、`npx vitest run scripts/app-privacy-docs.test.mjs`（17件成功）、`git diff --check`（成功）。コミットした画像は`SCREENSHOTS.md`に書いたコマンドでHTMLから作り、同じコマンドでもう一度作った画像とバイト単位で一致することを確かめた。読み取った範囲と計算した範囲に切り取った画像で、文字が切れないことを目で確かめた（範囲そのものの正しさは確かめていない）。App Store Connectのプレビューで見え方を確かめ直すのは、画像を差し替えてから利用者が行う。
- デプロイ影響: なし。Pagesは再配信されず、アプリのビルドにも影響しない。App Store Connectのヘッダの画像は、作り直したこの画像に差し替える。
