# 2026-10-21 — iOS版に入る言語を日本語だけにする

- 影響: `.knit`の種類名の英訳（`Knitting Chart Backup`）を外し、アプリに入る言語を`ja.lproj`だけにした。アプリの画面は日本語だけなので、App Storeの「言語」に英語が出て、英語で使えると誤解されるのを防ぐ。英語の端末でも、アプリの言語は日本語になり、Filesや共有シートに出る種類名と、ファイル選択などシステムが出す文言も日本語で出る。`.lproj`を1つも入れない形にすると、Foundationはどの端末でもアプリの言語を英語と判定するため、日本語の訳だけは残した。`Info.plist`に`CFBundleDevelopmentRegion`（`ja`）を足した。XcodeGenがプロジェクトの`knownRegions`から`en`を外した。種類の識別子と拡張子は変えていない。
- 主なファイル: `ios/App/InfoPlist.xcstrings`、`ios/App/Info.plist`、`ios/knittingEditor.xcodeproj/project.pbxproj`、`ios/scripts/check-app-bundle.sh`、`ios/Tests/KnittingEditorAppTests/KnittingEditorUTTypeTests.swift`、`ios/docs/APP_STORE_METADATA.md`
- テスト: `KnittingEditorUTTypeTests`を更新した。日本語の訳だけを確かめ、アプリに入る言語が`ja`だけであること、開発言語が`ja`であること、表示言語によらずシステムが日本語の種類名を返すことを確かめる（`testAppIsLocalizedOnlyIntoJapanese`、`testSystemDescribesKnitTypeInJapanese`）。`ios/scripts/check-app-bundle.sh`は、英訳の検査をやめ、`ja.lproj`以外の`.lproj`が入っていたら失敗するようにした。
- 検証: 手元（Xcode 27.1）で`cd ios && xcodegen generate --spec project.yml`を実行し、プロジェクトの差分が`knownRegions`の`en`の削除だけであることを確かめた。`xcodebuild build`（Debug、iOS Simulator）が成功し、できたアプリの`.lproj`が`ja.lproj`だけであること、`sh ios/scripts/check-app-bundle.sh <app>`が通ることを確かめた。`en.lproj`を足したコピーでは「unexpected localizations other than ja: en.lproj」で失敗することも確かめた。KE verify iPhone（iOS 27.0、Simulatorは1台だけ）で`-only-testing:knittingEditorTests/KnittingEditorUTTypeTests`の5件が成功し、ログは`app language = ja`だった。このSimulatorの表示言語での結果なので、英語の表示言語での経路はPRのCI（表示言語が英語）で確かめる。iPadの単体テスト・UIテスト、Release Archiveは、PRの`ios`ジョブとマージ前にブランチで手動実行する`ios-full.yml`に任せる。Webと`packages/`は変えていない。
- デプロイ影響: Pagesへの影響なし。次のiOSビルドから、App Storeの「言語」は日本語だけになる見込み。提出後に製品ページの「言語」の表示を確かめる。
