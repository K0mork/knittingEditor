# 2026-10-15 — 「ファイル」アプリで`.knit`をタップして開けることをiPad実機で確かめる

- 影響: アプリの動作は変えていない。「ファイル」アプリで`.knit`をタップするとアプリが開いて編み図を復元する変更（`LSSupportsOpeningDocumentsInPlace`を`true`にし、原本をアクセス権付きで読む）は、PR #155（`docs/dev-log/2026-10-09-open-knit-from-files.md`）で入った。そのときはSimulatorだけで確かめていて、実機ではアクセス権の制限がSimulatorより厳しいため、#149を開いたままにしていた。今回、iPad実機で利用者が手で確かめ、#149を閉じる。
- 主なファイル: `ios/App/Info.plist`、`ios/App/WebViewContainer.swift`（どちらも変更なし）
- テスト: 追加・更新したテストはない。「ファイル」アプリでのタップとAirDropの受け取りはXCUITestで操作できないため、利用者が実機で手で確かめた。
- 検証: PR #273のブランチ（`b1b88d7`。内容は`main`の`4eef16b`と同じで、PR #155を含む）を、Xcode 27.0・無料Personal Teamで署名してiPad Air 第5世代（iPadOS 27.0.1、有線）へ入れた。アプリの「この編み図を書き出す」から「このiPad内」と「iCloud Drive」へ`.knit`を保存し、利用者が次を確かめ、すべて期待どおりだった。
  - アプリを終了した状態で、「ファイル」アプリの「このiPad内」の`.knit`をタップすると、アプリが起動して「1件の編み図を復元しました」と出て、「（復元）」の付いた編み図ができた。元の`.knit`は「ファイル」アプリに残った。
  - アプリを開いた状態で、「iCloud Drive」の`.knit`をタップしても同じく復元され、元のファイルは残った。
  - 「ファイル」アプリの共有メニューから「棒針編み図」を選んだときと、MacからAirDropで受け取った`.knit`を開いたときも、今までどおり復元された。
  - 確かめていないこと: iPhone実機（接続できなかった）。PR #155ではiPhoneでの確認を予定していたが、アクセス権の扱いはiPhoneとiPadで同じ仕組みのため、iPadの結果で#149を閉じる。
  - `git diff --check`と`ios/scripts/check-app-store-docs.sh`が成功した。文書だけの変更のため、Web・iOSのテストは手元で実行していない。
- デプロイ影響: なし（文書だけ）。
