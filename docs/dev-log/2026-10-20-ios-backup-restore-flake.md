# 2026-10-20 — 保存・復元UIテストの効かなかったタップだけ押し直し、失敗の記録を残す

- 影響: `testBlockSaveAndFullBackupRestoreFollowGuide` の断続的な失敗への対処。iPhoneでは「Browse」から保存場所の一覧へ戻る途中のタップが効かず、一覧に残ったため、保存場所の静止を待ってから押す。バックアップのセルが10秒で押せず、保存場所がまだ画面内で押せる場合だけ画面写真を添付し、静止を待って1回押し直す。最後は残り20秒待ち、選べなければ従来のメッセージで失敗する。iPadでは盤面の静止後でも描画のタップが効かず記号数が変わらなかったため、冒頭の3マスの描画だけ、10秒で増えず元の記号数の盤面がある場合に画面写真を添付し、再度静止を確かめて1回押し直す。最後の記号数の確認は従来どおりとし、他のテストのタップは変えない。iOS全検証ではxcresultとxcodebuildのログを生成し、再試行で成功した場合を含めテストケースの失敗行がある場合、またはジョブが失敗した場合に、端末別・実行試行別のアーティファクトとして7日間保存する。`tee`を使い、`pipefail`でテスト失敗の終了コードを保持する。
- 主なファイル: `ios/UITests/KnittingEditorUITests/KnittingEditorUITests.swift`、`.github/workflows/ios-full.yml`
- テスト: `testBlockSaveAndFullBackupRestoreFollowGuide` の描画ループと復元の保存場所選択ヘルパーを更新。各押し直しは効いていないと確認できる場合だけ1回に限定し、押し直しても進まなければ失敗する。
- 原因: #297 のマージ後の main の Full iOS validation で、このテストが1回目に失敗し、再試行で成功した2件。iPhone 17（run 39370005510、`:1910`）は、一意の名前で保存できた後、復元の選択画面で「Browse」を2回押した約1.9秒後に「On My iPhone」を押したが、保存場所の一覧のまま30秒進まなかった。iPad (A16)（run 39379438788、`:433`→`:377`→`:384`）は、盤面の静止を確かめた後の1マス目のタップで記号が0個のまま増えなかった（押した位置は盤面内、キーボードやダイアログは無し）。どちらも、これまでの hittability の問い合わせ・置き換えの停止・iPhoneで入力欄が出ない件とは別の原因。xcresult が CI に残っていなかったため、iPad のタップが効かなかった理由は特定できていない。
- 検証: Codex が `git diff --check`、`node scripts/check-pr-smoke-ui-tests.mjs`、`ruby -ryaml -e 'YAML.load_file(".github/workflows/ios-full.yml")'`、`xcodegen generate --spec ios/project.yml` を実行して成功し、ワークフローの判定スクリプトを抜き出して、成功のみ・初回失敗後に成功・失敗の各ログで失敗の有無と端末名の変換、`pipefail` による終了コードの保持を確かめた。手元（Xcode 27.1、iOS 27 の Simulator）で `xcodebuild test -only-testing:knittingEditorUITests/KnittingEditorUITests/testBlockSaveAndFullBackupRestoreFollowGuide -test-iterations 3 -run-tests-until-failure` を実行し、KE verify iPhone で3回、KE verify iPad で3回続けて成功した。手元の KE verify iPad では、その前に2回失敗しており、どちらも環境の要因と判断した。1回目はテスト開始前に「Failed to prepare device … Invalid connectionUUID specified」で止まり（テストケースは未実行）、Simulator を止めて起動し直した。2回目は、Mac の負荷が非常に高い時間帯に、1マス目を押す前の盤面の静止待ち（`positionSaveProbeCanvas` の10秒、`:377`）が切れた。文字入力や「決定」の押下に数秒かかり、パネルの「閉じる」が消えるのも遅れていた。今回の変更より前の箇所で、押し直しの処理には届いていない。負荷が下がった後の3回は成功した。静止待ちの上限は変えていない。ブランチでの `ios-full.yml`（run 39390701235、`e5495a6`）は全ジョブ成功し、このテストは iPhone 17・iPad (A16) とも1回目で通り、どのテストにも再試行は無かった。押し直しの経路は、CI でも手元でも一度も使われなかった。失敗が無かったため、xcresult を残す手順は判定とアップロードのスキップだけが動き、実際のアップロードはまだ一度も動いていない（アップロードの手順は `continue-on-error` で、失敗してもジョブの結果は変わらない）。PR の CI の結果は PR に記録する。
- デプロイ影響: なし。iOSのテストとiOS全検証のワークフローだけで、Pagesの配信物は変わらない。
