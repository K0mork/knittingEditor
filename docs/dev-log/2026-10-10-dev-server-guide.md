# 2026-10-10 — 開発サーバーで静的ページのディレクトリURLを配信

- 影響: Vite開発サーバーで、編集画面の「使い方」から`/guide/`を開くと編集画面が出ていたのを直した。`/guide/`、`/support/`、`/privacy/`など、`public/`配下に`index.html`があるディレクトリURLを、開発時にも静的ページとして配信する。対象は`public/`配下のディレクトリだけで、ビルド時に生成する`/third-party-notices/`は、開発サーバーでは従来どおり編集画面を返す。末尾スラッシュのない`/guide`も開発サーバーでは編集画面のまま（アプリ内のリンクは`/guide/`）。プラグインは開発サーバーだけに適用し、本番ビルドとpreviewには適用しない。Closes #216。
- 主なファイル: `vite.config.ts`、`scripts/public-directory-index.mjs`、`scripts/public-directory-index.d.mts`。
- テスト: `scripts/public-directory-index.test.mjs`を足した（実際の開発サーバーに対し、ディレクトリURL、クエリ、明示的な`index.html`、HEAD、ルートと存在しないディレクトリの編集画面へのフォールバック、静的アセットを確認）。`tests/e2e/dev-guide.spec.ts`を足した（テスト自身が開発サーバーを起動し、編集画面から使い方へ移動して再読み込みする）。
- 検証: Node v24.21.0で`npm ci`、`npm run typecheck`、`npm test`（38ファイル263件）、`npm run build`、`npm run check:dist`を実行し、成功した。`npm run dev -- --host 127.0.0.1 --port 5419 --strictPort`で起動した開発サーバーに対し、`curl -fsS http://127.0.0.1:5419/guide/ | cmp - public/guide/index.html`とsupport・privacyの同じ比較が成功し、`/`が`/@vite/client`を含む編集画面を返すことを確かめた。`dist/CNAME`が`knittingeditor.com`であること、`dist/index.html`と`dist/guide/index.html`のタイトルと`/assets/`参照を確かめた。プラグインの有無で`npm run build`した`dist/`全18ファイルのSHA-256が一致し、ビルド出力が変わらないことを確かめた。プラグインを一時的に外すと、`scripts/public-directory-index.test.mjs`は4件中3件（guide・support・privacy）、`tests/e2e/dev-guide.spec.ts`は3プロジェクトとも失敗し、curlでも`/guide/`・`/support/`・`/privacy/`が編集画面になって不具合を再現した。`/guide/?a=1`、`/guide/index.html`、HEADは使い方ページを返し、POSTは従来どおり404、`/missing/`・`/assets/`・`/src/`・`/guide`と`public/`の外を指すパス（`/%2e%2e/`など）は編集画面へフォールバックした。`npx playwright test tests/e2e/dev-guide.spec.ts`はchromium-mobile・webkit-mobile・chromium-desktopの3プロジェクトで2回とも成功し、Viteの依存キャッシュ（`node_modules/.vite`）を空にした状態でも2回とも成功した。`npx playwright test`（`npm run test:e2e`と同じ全体）は2回実行し、2回目は167件成功（4件スキップ）。1回目は変更と関係しない`tests/e2e/document-list.spec.ts:97`（webkit-mobile、盤面を1000段に変えたあとの5秒の待ち）が1件時間切れで失敗し、166件成功（4件スキップ）だった。この1件は単独で3回繰り返して9件とも成功した。iOSのソースと`ios/Web`の設定はこのプラグインを読み込まないので、iOSの確認は手元では実行せず、PRのCIのWeb・iOSの各ジョブに任せる。
- デプロイ影響: なし。開発サーバーだけの変更で、ビルド出力は変わらない。配信後に追加で確かめることはない。
