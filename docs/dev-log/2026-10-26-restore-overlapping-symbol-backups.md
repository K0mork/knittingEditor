# 2026-10-26 — 記号が重なった編み図・ブロックを含むバックアップを復元できるようにする

- 影響: #157の修正前の段・列の削除では、記号の起点が重なった盤面が保存され得た。この盤面を含む全データバックアップは「盤面データが重複しています」で全体が拒否され、正常な編み図も復元できなかった。読み込むとき、行優先で先に受け入れた起点を残し、それと重なる記号を記号単位で除くようにした（管理者が決定）。保存済みの盤面を開くとき（元に戻す・やり直すの復元を含む）、`.knit`から復元するとき、一覧の縮小画像で同じ規則を使う。開いただけでは保存済みの原本を書き換えず、編集して保存したときに修復した盤面を保存する。同じ盤面から作ったブロックにも重なった記号が入り得て、全データバックアップは「ブロックの記号が重複しています」で全体が拒否され、貼り付けでは後の記号が残っていた。ブロックも復元時と貼り付け時に、記号の並びで先の記号を残し、重なる記号を除くようにした（管理者が決定。ブロックの記号は行優先で保存されるので盤面と同じ規則になる）。重なったブロックを拒否していた既存テストは、先の記号を残して復元するテストへ書き換えた。保存形式・schema・記号IDは変えず、未知の記号とはみ出す記号を破損として拒否する検査は、盤面・ブロックとも残した。
- 主なファイル: `packages/editor-core/model/Board.ts`（読み込みと`pasteBlock`）、`packages/editor-core/storage/backupCodec.ts`、`packages/editor-core/model/thumbnail.ts`、`tests/e2e/overlapping-stitch-repair.spec.ts`。
- テスト:
  - Vitest: 重なった盤面の読み込みで先の起点を残し、所有情報と記号数が一致し、残した記号を1つの単位で消せ、`restore`でも同じになること（`Board.test.ts`）。重なった編み図と正常な編み図を含むバックアップの書き出し→復元で、正常な編み図が変わらず、修復結果が`Board`の読み込みと一致し、再度の往復でも変わらないこと。はみ出す記号は引き続き拒否すること（`backupCodec.test.ts`）。IndexedDBへの復元（`database.test.ts`）。縮小画像で重なる記号を描かないこと（`thumbnail.test.ts`）。重なったブロックの貼り付けで先の記号を残すこと（`Board.test.ts`）。重なったブロックを含むバックアップを編み図と一緒に復元でき、先の記号だけが残ること、はみ出すブロックの記号は引き続き拒否すること（`database.test.ts`）。
  - Playwright: IndexedDBへ直接入れた重なった編み図を開くと先の記号を残し、開いただけでは原本を書き換えないこと。重なった編み図を含む全データバックアップを書き出して2件とも復元できること。編集すると修復した盤面を保存し、再読み込みしても変わらないこと。全データバックアップの復元で、重なったブロックも先の記号だけを残して復元し、原本のブロックは変えないこと。重なった保存済みブロックを貼り付けると先の記号を残すこと。修正前のコードでは開く・編集の2件が、貼り付けの修正を外すと貼り付けの1件が、それぞれ失敗することを確かめた。
