# 2026-11-11 — iOSのアップデート確認が時間切れで落ちないようにし、失敗を調べられるようにする

- 影響: `Full iOS validation`の`app_update (iPhone 17)`が、11-04と11-10に`testSeedDocumentForAppUpdateProbe`の時間切れで失敗した（#441）。上限の180秒を超えると、`-retry-tests-on-failure`の2回目が0件で終わり、ジョブが失敗する。11-04はテスト自体は成功していたが209.8秒かかり、11-10は「編み図」を2回押してもパネルが開かなかった。10-28以降のapp_update 104ジョブでは、起動直後の「編み図」の1回目のタップが約半数で効かず、押し直しで開いていた。原因はまだ分からないので、次の3つを入れて次の発生を待つ。
  - `ios/scripts/simulate-app-update.sh`: 両方のテストの実行時間の上限を240秒（既定・最大とも）にした。時間切れではなく普通の失敗になれば、2回目が流れる。テストの結果を`APP_UPDATE_RESULTS_DIR`（既定はスクリプトの作業用ディレクトリ`$TMPDIR/knitting-editor-app-update-<端末名>`の`results`）に`seed.xcresult`・`restore.xcresult`として書き出す。
  - `.github/workflows/ios-full.yml`: `app_update`ジョブが失敗したとき、または再試行で通ったテストの1回目が失敗していたときに、テストの結果とログをartifact（7日）に残す。`ios_full`ジョブと同じ条件。
  - `openDocumentsPanel`（UIテスト）: 準備中の表示（`editorLoadingOverlay`）が消えるのを待ってから「編み図」を押す。各タップの前に、準備中の表示の有無と押せるかを記録し、押し直したときは画面写真を添付する。1回目で開かなかったときと準備中の表示が消えなかったときは、経過を`TAPRETRY 編み図`としてジョブログにも出す。
  - 更新前のアプリのテストは前のリリースのタグ（今は`ios-v1.1-build1`）から作るので、`openDocumentsPanel`の変更が`testSeedDocumentForAppUpdateProbe`に効くのは、次のリリースのタグを付けたあと。更新後のテストと`ios_full`には今から効く。
- 主なファイル: `ios/scripts/simulate-app-update.sh`、`.github/workflows/ios-full.yml`、`ios/UITests/KnittingEditorUITests/KnittingEditorUITests.swift`
- テスト: UIテストの補助（`openDocumentsPanel`）を変えた。テストの追加はない。
- 検証: 手元（Xcode 27.2、KE verify iPhone＝iPhone 17・iOS 27.2）で`SIMULATOR_UDID=<UDID> APP_UPDATE_RESULTS_DIR=<dir> ios/scripts/simulate-app-update.sh "iPhone 17"`を実行して成功した（`ios-v1.1-build1`からの更新。fixtureの作成33.2秒、更新後の確認16.1秒。`seed.xcresult`と`restore.xcresult`が書き出された。更新後の確認では、変更後の`openDocumentsPanel`の1回目のタップでパネルが開いた）。この実行のあとで、`results_dir`を絶対パスにする変更と、「編み図」が無いときに押せるかを読まない変更を入れた（下の静的な確認と型検査で確認）。`bash -n ios/scripts/simulate-app-update.sh`、`ios-full.yml`をYAMLとして読んで`app_update`の手順と条件を確認、`node scripts/check-pr-smoke-ui-tests.mjs`（PRスモーク11件、実機14件）、`sh ios/scripts/check-app-store-docs.sh`、`npx vitest run scripts/ios-full-failure.test.mjs`（23件）、`xcrun --sdk iphonesimulator swiftc -typecheck`（UIテストの3ファイル）、`git diff --check`（いずれも成功）。Node.js v26.8.1。ブランチで手動実行した`Full iOS validation`（run 42967776853、`500bca7`、Xcode 26.6）: `ios_full`（iPhone 17・iPad (A16)）、`app_update`（iPhone 17・iPad (A16)）、`release_archive`がすべて1回目で成功した。4つのテストジョブのログに`Iteration 2 of 2`・`exceeded execution time allowance`・`Restarting after unexpected exit`・`TAPRETRY`は無く、`app_update`の新しい手順`Find failed app update tests`が動いた（失敗が無いのでartifactは作られない）。`testSeedDocumentForAppUpdateProbe`はiPhoneで58.7秒、iPadで46.7秒。
- デプロイ影響: なし。サイトとアプリの内容は変わらない。マージ後の`Full iOS validation`で、両方の`app_update`が成功することを確かめる。#441は原因が分かるまで開いたままにする。
