# 2026-10-09 — iOS版で準備中の表示から編集画面へ切れ目なくつなぐ

- 影響: iOS版の起動時などに、準備中の表示（「編み図を準備しています…」）が消えてから編集画面が出るまでの0.2〜0.3秒ほど、編集画面の地の色の画面とWeb側の「編み図を読み込んでいます…」が見えていたのを直した（#117の1つ目）。Web側が`webReady`を送る時期を、Reactの最初の描画の直後から、端末内データを読み込んで編集画面と盤面を描き、それが画面に出たあと（`requestAnimationFrame`を2回待つ）に変えた（`ios/Web/src/editorReady.ts`）。読み込みに失敗したときは、失敗の理由を出してから送る。読み込みが止まった場合も、10秒のタイムアウトで失敗の画面を出してから送るので、準備中の表示が出たままにはならない。`.knit`の受け渡しとメニューの操作も、この`webReady`のあと、つまり端末内データの読み込みが終わってから始まる。バックアップイベントの購読は今までどおりReactの最初の描画で済ませるので、`webReady`の時点では購読が終わっている。Swift側は、`webReady`を受けると準備中の表示を0.2秒で薄くして消す。「視差効果を減らす」がオンのときはすぐ消す。使い方ページから編集画面へ戻るときは、準備中の表示をすぐ出して覆う（出すときは動かさない）。消える動きは、WebViewからの通知で状態を変えるところ（`WebViewModel.webContentDidBecomeReady`）で`withAnimation`を使って付け、`ZStack`で取り除く途中の準備中の表示がWebViewの後ろへ回らないよう重ね順（`zIndex`）を固定した。#117の2つ目（iOS 27のSimulatorで起動画面の緑が準備中の表示より鮮やかに見える件）は実機での確認が必要なので、このPRでは扱わない。
- 主なファイル: `ios/Web/src/editorReady.ts`、`ios/Web/src/App.tsx`、`ios/App/KnittingEditorApp.swift`、`ios/App/WebViewContainer.swift`、`ios/docs/NATIVE_BRIDGE.md`、`ios/docs/WEB_SYNC.md`
- テスト: `ios/Web/src/editorReady.test.ts`を足した（次の描画のさらに次のフレームまで待つこと、途中で取り消せること、編集画面を出せるまでは送らず、出せたら描画のあとで一度だけ送り、再描画や表示の切り替えでは送り直さないこと）。iOSの`AppAppearanceTests`に、準備中の表示が0.2秒の`easeOut`で消え、「視差効果を減らす」がオンなら動かさずに消えることを確かめるテストを足した。
- 検証: iOS Webの型検査（`ios/Web`で`tsc -p tsconfig.app.json --noEmit`）とテスト（`vitest run --config vite.config.ts`、8ファイル34件）、ルートの`npm run typecheck`と`npm test`（37ファイル254件）を実行し、成功した。Web版と共通コード（`packages/`）は変えていないので、`npm run build`・`npm run check:dist`・`npm run test:e2e`は実行していない。手元のNode.jsは26.8.1で、指定の24ではない。iOSは手元で`xcodegen generate`と、iPhone 16のSimulatorでのビルドと単体テスト（`knittingEditorTests`、78件、既存の1件はスキップ）を実行し、成功した。iPhone 16のSimulatorで、ライト・ダークそれぞれの起動を画面収録し、直す前の録画と比べた。直す前は準備中の表示の緑のあとに「編み図を読み込んでいます…」の画面がライトで約0.23秒、ダークで約0.33秒出ていたが、直したあとは出ず、緑から編集画面へ約0.17秒で色が移った。Simulatorの録画はコマの間隔が一定でなく0.2秒の動きを捉えにくいので、一時的に消える時間を2秒にしたビルドで、途中の色が少しずつ変わることも確かめた（確認後に0.2秒へ戻した）。UIテストを含むSimulatorのテスト全体、更新復元、アプリのArchiveはPRのCIで確かめる。
- デプロイ影響: なし（iOSのみの変更で、Pagesは再配信されない）。
