# 2026-11-10 — iPadのハードウェアキーボードのdeleteキーで選択範囲を消す

- 影響: iPadにハードウェアキーボードを接続したとき、範囲を選んでdeleteキーを押すと、画面の「消去」と同じ処理で選択範囲の記号と線を消せるようになった（#428）。メニューバーの「編集」メニュー、「すべてを選択」の後ろに「選んだ範囲を消去」（delete、修飾キーなし）を置いた。Web側から送る`canEraseSelection`が真のときだけ選べる。範囲が無いとき、入力欄で文字を打っているとき、ダイアログや記号の一覧を開いているときは選べず、deleteは入力欄の文字を消す標準の操作へ渡る。出力・復元の処理中は画面の「消去」ボタンと同じく選べて実行できる。1回のキー入力で消去は1回、履歴も1件だけ積む。Web版（ブラウザ）の挙動は変えていない。
- 原因: iPadOS 27.2・Xcode 27.2のSimulatorで測ると、盤面（入力欄以外）にフォーカスがあるとき、WKWebViewはハードウェアキーの押下をページの`keydown`へ渡さない。deleteだけでなく`x`も届かず、ページの`useEraseShortcuts`（`packages/editor-core/ui/hooks.ts`）は呼ばれない。これが#428の原因だった。入力欄では`keydown`が届き、deleteで1文字消える（origin/mainでも正常）。選べる状態のメニュー項目はUIKitがdeleteを受け取り、無効なときはキーが入力欄へ渡る（入力欄にフォーカスがある場合）。このため、ページ側に同じキーを受ける受け口や重複排除は置かず、メニュー項目と`eraseSelection`コマンドだけで動かす。
- 主なファイル: `ios/App/EditorCommands.swift`, `ios/App/WebViewModel.swift`, `ios/App/NativeBridgeMessage.swift`, `ios/Web/src/nativeBridge.ts`, `ios/Web/src/nativeCommands.ts`, `ios/Web/src/App.tsx`, `ios/Tests/KnittingEditorAppTests/EditorCommandsTests.swift`, `ios/Web/src/nativeCommands.test.ts`, `ios/Web/src/App.eraseCommand.test.tsx`, `ios/UITests/KnittingEditorUITests/KeyboardCommandUITests.swift`, `ios/Web/public/guide/index.html`, `ios/docs/APP_REVIEW_NOTES.md`, `ios/docs/NATIVE_BRIDGE.md`
- テスト: `EditorCommandsTests.swift`で`eraseSelection`の名前・選択条件（準備前、ネイティブ画面表示中、範囲あり）と`commandState`の`canEraseSelection`のデコード（無い古いbundleは偽、Boolでない値は拒否）を確かめる。`nativeCommands.test.ts`で消去が`editor.eraseSelection`へ届くこと、処理中でもほかの操作と違って実行できること、入力欄では`execCommand('delete')`で1文字消して盤面を触らないこと、`nativeEraseSelectionState`が範囲・入力欄・モーダルに追随することを確かめる。`App.eraseCommand.test.tsx`では`listenNativeCommand`を実物と同じwindow購読のモックにし、メニューのコマンドが実際に配線を通ること、1回で1回だけ消すこと、入力欄・モーダル・処理中の扱い、`canEraseSelection`の通知を確かめる。`KeyboardCommandUITests.swift`に、範囲を選んでdeleteで消し⌘Z1回で戻すテスト、範囲を選んだままモーダルでない「段数」欄にフォーカスしてdeleteを押すと入力欄の文字だけが1文字消えて盤面が変わらないテスト、⌘Nダイアログの入力欄で1文字だけ消えるテストを追加。`typeDelete`はXcode 27.2の`typeKey`が`XCUIKeyboardKey.delete`（U+007F）を送れないため、記号の「⌫」（U+232B）を使う。
