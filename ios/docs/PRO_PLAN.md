# 有料機能（Pro）実装検討

iOS版に買い切りのアプリ内課金「Pro」を追加するための検討メモ。**まだ実装しない。** 実装に入るときはこの文書を仕様の起点にし、確定した内容を`SPECIFICATION.md`・`NATIVE_BRIDGE.md`・`WEB_SYNC.md`へ移す。

## 1. 方針

- Web版で無料で使える機能は、アプリでも制限しない。PDF出力・盤面サイズ・編み図の枚数・ブロックは無料のまま。
- Proには、**Web版にないアプリ専用の機能だけ**を入れる。無料Web版で代替できるPDF出力などを購入理由にしない。
- 購入理由は、**自作の編み図で、制作から実際に編むところまで完結すること**。図案の書き出しや別アプリへの取り込みをせず、誤編集を防いで現在段を確認し、翌日も続きから再開できる便利さを提供する。「Web版にない」ことだけで購入需要があるとは判断しない。
- 広告・サブスクリプション・分析SDKは入れない。「オフライン・広告なし・トラッキングなし」というアプリの前提を変えない。
- **初回リリース（v1.0）は今の仕様のまま、無料版のみを公開する（確定方針）。課金やProの実装を初回公開の前提にしない。** Proはv1.1以降に追加する。v1.0にある機能は有料化しないので、既存利用者の優遇措置（grandfathering）は不要。
- 編み進めモードの無料範囲と買い切り価格は、**未購入者が使い始める前に明示する**。11段目で初めて有料と分かる導線にしない（§3.8・§5.4）。

## 3. 編み進めモード（第1弾）

編み図を作り終えた後、実際に編むときに使う表示専用のモード。今編んでいる段をハイライトし、編み図に触れても書き換わらないようにする。

### 3.1 入り方・抜け方

- iOS版だけ、操作メニュー（`action-bar`）に「編む」ボタンを出す。Web版にはボタンを出さない。
- 編み進めモードの間は、上の道具列（色・記号・描く／消す／範囲・貼付）と、元に戻す／やり直すを隠す。代わりに「編集に戻る」ボタンと現在の段を表示する。
- 入る前に進行中の編集を確定し、保留中の盤面保存を完了させる。保存が失敗・保留中ならモードを切り替えず、編み図を保つ。
- 開いていたパネル・選択範囲・貼り付け待ちは、入るときに解除する。
- 編集に戻ると、直前の描画モード（`draw`など）へ戻る。

### 3.2 編集禁止（誤タップ防止）

編み進めモードでは、盤面を書き換える経路をすべて止める。

- タップ・なぞり描き・消去・範囲選択・貼り付けを行わない。
- 右クリック消去（`event.button === 2`）を行わない。
- キーボードショートカット（Cmd/Ctrl+Z、Shift+Cmd+Z、Ctrl+Y、Cmd/Ctrl+C／V）を無効にする。
- 盤面設定・ブロック・編み図のパネルは開けないようにする。
- モード中の盤面操作では`onChange`・`onEditEnd`を呼ばず、新しい盤面変更や編集履歴を作らない。入る前の盤面保存と、段番号の保存（§3.6）は別に行う。

### 3.3 1本指での縦横スクロール

- 1本指のドラッグで、盤面を縦横どちらにも動かす。前回の指の位置との差分だけ`viewport`を動かす。
- 2本指のピンチ拡大・移動、マウスホイール、トラックパッドは今の動作のまま。
- 1本指から2本指に変わったときは、今の`gestureRef`の処理へ切り替える。2本指から1本指に戻ったときは、残った指の位置を新しい起点にしてから1本指のスクロールを続ける（盤面が飛ばないように）。
- タップには何も割り当てない。タップでハイライトを移す機能は、誤タップ防止の目的と矛盾するので入れない。
- 慣性スクロールは第1弾では入れない（未決事項を参照）。

### 3.4 段のハイライト

- ハイライトする単位は**段（行）全体**。
- 段番号は盤面の表示と同じく下から数える（`段番号 = board.rows - 行index`）。最初は1段目（いちばん下の行）から始める。
- 描き方:
  - 対象の段に半透明の帯を重ね、上下に枠線を引く。
  - 左端の段番号ラベルも強調表示する。
  - 他の段を少し暗くするかどうかは試作して決める。
- 盤面の段数が減って保存済みの段番号が範囲外になったときは、最終段に丸める。

### 3.5 段送りボタン（∧ ∨）

- 上向き（∧）と下向き（∨）の山形のボタンを、盤面の上に重ねて置く。
  - ∧＝次の段（段番号＋1。編み進む方向は上）。
  - ∨＝前の段（段番号−1）。
- 1段目で∨、最終段で∧を押しても動かない。端に着いたらボタンを無効表示にする。
- 配置と見た目:
  - 盤面右端の下寄りに、縦に2つ並べる。
  - 左端の段番号ラベル（28px）や、下の操作メニューには重ねない。
  - Safe Areaの内側に収める。
  - 1つ48×48pt（仕様書の44pt以上を満たす）、角丸または円形。
  - 普段は不透明度0.45程度、押している間だけ0.9程度にして、下の編み図が透けて見えるようにする。
- ボタンの近くに小さく「12段 / 80段」を表示する。
- 段を送ったとき、ハイライトが画面外に出そうなら、縦方向だけ自動でスクロールして表示範囲の中央付近に保つ。横方向の位置は変えない。
- 押し続けたときの連続送りは第1弾では入れない（未決事項を参照）。
- iPadのハードウェアキーボードでは、↑・↓キーでも段を送れるようにする。
- **指定段への移動を第1弾に含める。** 現在段の表示から段番号を入力し、途中まで編んだ作品を再開できるようにする。整数・盤面の段数・無料範囲を検証し、無料範囲外なら移動前に購入案内を出す。盤面へのタップには割り当てない。
- VoiceOver:
  - ボタンのラベルは「次の段へ」「前の段へ」。
  - 段を送るたびに`aria-live`で「12段目」と読み上げる。

### 3.6 進み具合の保存

- 編み図ごとに現在の段番号を保存し、モードに入り直したときやアプリを再起動したときに復元する。
- 復元した段番号にも§3.8の利用権限を適用する。購入状態を確認中の場合や、購入権限が失効した場合も、保存済みの進捗を勝手に10段へ上書きしない。
- 保存先は既存IndexedDBの`settings`ストア。**Pro用と試用用を別キーで永続保存する。試用中の段番号をメモリ上だけには持たない。** どちらも値は段番号で、DBのバージョンもストアの構成も変えない。
  - Pro用：`knitProgress:<文書ID>`。有効な購入権限があるときの初期化・段送り・指定段への移動だけが更新する。
  - 試用用：`knitTrialProgress:<文書ID>`。試用中の初期化・段送り・指定段への移動だけが更新する。値の範囲は`1〜min(10, board.rows)`。
- 未購入者の試用開始・再入場・再起動では試用用キーから復元し、未保存なら1段目から始める。元のPro用キーは読んでも書き換えず、無料範囲への丸め結果もPro用キーへ保存しない。購入状態の確認中もPro用キーは更新しない。
- 購入・復元によって有効な権限を確認した後は、保存済みのPro用進捗があればそこから再開する。Pro用進捗がなければ試用用進捗（それもなければ1段目）を初期値としてPro用キーへ保存する。既存のPro用進捗を試用用進捗で自動上書きしない。§5.4の同じ文書・モードで待っている明示的な移動要求がある場合に限り、要求先へ進んでPro用キーを更新する。試用用キーは購入・復元時にも保持する。
- 段番号は表示上の番号（下から数えた段）で持つ。上に段を足しても、編んでいる段の番号は変わらない。
- 第1弾の`.knit`バックアップ（version 2）にはPro用・試用用のどちらの進捗も含めない。**図案は復元できるが、どこまで編んだかは復元されない**ことを使い方とバックアップ案内に明示する。第2弾での扱いは§4のとおり設計する。
- 編み図を削除したときは、対応するPro用・試用用の両キーも削除する。複製した編み図にはどちらも引き継がない。
- 保存失敗の通知、段送り直後のバックグラウンド移行、文書削除と進捗書き込みの競合を扱う。段の挿入・削除やUndo／Redo後にどの段を追うかは、実装前に仕様を確定する。

### 3.7 画面の自動消灯の防止

- 編み進めモードの間は`UIApplication.shared.isIdleTimerDisabled = true`にする。
- モードを抜けたとき、アプリがバックグラウンドへ移ったとき、使い方ページへ移るときは`false`に戻す。
- フォアグラウンドに戻ってまだ編み進めモードなら、再び`true`にする。

### 3.8 無料で試せる範囲と、開始前の説明（必須）

**使い始める前に、無料範囲・全段利用の価格・買い切りであることを伝える。11段目で初めて課金を知らせる仕様にはしない。**

- 未購入者向けの入口は「編む（10段まで無料）」など、無料範囲が分かる表示にする。モードへ入る前の案内に「編み進めモードは1〜10段まで無料で試せます。全段利用はProの買い切り〈displayPrice〉です。追加の定期料金はありません。」と表示する。
- 開始前の案内には「無料で試す」「Proの購入・復元」「閉じる」を置く。購入は試用開始の条件にせず、購入ボタンを押すまで決済を開始しない。
- **価格はStoreKitの`displayPrice`を使う。** 取得できない場合は「1〜10段まで無料。全段利用はProの買い切りです。現在の価格はオンラインで確認できます。」と案内する。価格不明でも無料体験は始められる。未確認の価格を表示して購入させない。
- 無料体験中も「無料体験：10段まで」と表示し、購入による全段利用と混同させない。購入済みの人には試用案内を出さない。
- 無料で進める範囲は`1〜min(10, board.rows)`段。11段目以降への操作は、実行前に購入案内を出す。編集・閲覧・PNG/PDF出力・手動バックアップには制限を加えない。
- 判定は段送りボタンだけでなく、↑↓キー、指定段への移動、保存済み進捗からの再入場にも共通で適用する。返金やファミリー共有の権限変更も反映する。
- 保存済みのPro用進捗が11段以上で未購入の場合は、開始前に購入・復元か「10段まで試す」を選べるようにする。試用中は§3.6の`knitTrialProgress:<文書ID>`へ保存・復元し、元の`knitProgress:<文書ID>`は変更しない。試用や権限失効だけで元の進捗を消さない。
- 段番号で範囲を判定し、試用回数は数えない。10段以下の図案や無料範囲を繰り返し使えることは、この方式の仕様として受け入れる。
- Pro公開時のApp Store説明とアプリ内の使い方にも、編集・出力は無料、編み進めモードは10段まで無料、全段利用は買い切りであることを書く。

## 4. 自動バックアップ（第2弾）

第1弾の後に設計を詰める。現時点の方向性だけを残す。

- 利用者がFilesで選んだフォルダ（iCloud Driveも可）へ、`.knit`を自動で書き出す。
- フォルダはsecurity-scoped bookmarkで覚える。
- 自動バックアップは利用者が保存先を選んで有効にする。iCloud Driveを選んだ場合の同期はファイルプロバイダが行い、オフライン中のクラウドへの配送完了までは保証しない。
- 書き出す前に保留中の盤面保存を完了させる。保存失敗・保留中のデータを「最新のバックアップ」と扱わない。
- 編集があった場合、フォアグラウンド中にも適切な間隔で書き出す。バックグラウンド移行時だけに頼らず、OSの実行時間制限や中断を扱う。[Appleのバックグラウンド処理仕様](https://developer.apple.com/documentation/backgroundtasks/choosing-background-strategies-for-your-app)
- 世代を数個残す。**新しい世代の書き込み成功を確認してから**古いものを消す。書き込み失敗時は既存のバックアップを保ち、消してよいのはアプリ自身が書いたファイルだけ。
- フォルダへのアクセス喪失、bookmarkの失効、容量不足、ファイルプロバイダの一時的な失敗を検出し、再試行や保存先の再選択を案内する。
- 書き出す中身は既存の`.knit`形式（version 2）。形式は変えない。
- `.knit`の復元で戻せる図案と、現形式では戻せない進捗を区別する。第2弾の設計時に、Web版との互換性を維持して進捗も保存・復元する方法を検討する。含めない場合は設定画面・購入案内・使い方にその制約を明示し、「編んでいた続きまで復元できる」と約束しない。
- 第2弾の提供時期・進捗の扱い・保存先の失敗処理は未確定。第1弾の購入案内で提供を約束しない。

## 5. 購入処理（StoreKit 2）

### 5.1 Swift側

- 起動時に`Transaction.updates`を購読し、外部での購入・返金・ファミリー共有の変化を反映する。
- 購入済みかどうかは`Transaction.currentEntitlements`で判定する。
  - 署名の検証に通ったもの（`VerificationResult.verified`）だけを有効とする。
  - `productID`がProの商品ID、`productType`が非消耗型であることも確認する。
  - `revocationDate`があるもの（返金されたもの）は無効とする。
- 端末内で確認できる有効な検証済み取引により、**オフラインでも購入済みのProを使える**。別端末での初回認識や再インストール後の復元にはオンラインでの確認が必要になる場合がある。単純なローカル真偽値だけを利用権限の根拠にしない。
- 価格表示は`Product.products(for:)`で取得した`displayPrice`を使う。Web側に「1,200円」を書き込まない。
- 価格や商品を取得できないときは、購入ボタンを無効にして再試行を案内する。取得失敗を必ずオフラインと断定しない。**価格取得と購入権限の判定は分離し、価格取得に失敗しても購入済みProは使える**ようにする。
- 購入は`product.purchase()`。結果は次のように扱う。
  - `success`：取引の署名・商品ID・商品種別・失効状態を確認し、有効なら機能を解放して利用権限を更新する。**解放後に`transaction.finish()`を呼ぶ**。未検証の取引では解放せず、検証失敗を通知する。
  - `userCancelled`：何も表示しない。
  - `pending`：「購入手続きの完了待ちです」と表示する。Ask to Buyに限定せず、後で`Transaction.updates`へ届く取引を検証して解放する。
- `Transaction.updates`から受け取った取引も検証し、有効なら解放、返金等で失効していれば権限を更新する。検証済み取引は変更の反映後に`finish()`する。重複通知で進捗を二重に送らない。[Appleの購入結果仕様](https://developer.apple.com/documentation/StoreKit/Product/PurchaseResult)
- 購入の復元は、利用者が「購入を復元」を押したときに`AppStore.sync()`を呼び、最新の利用権限を再確認する。復元処理の失敗で既存の検証済み利用権限を勝手に取り消さない。
- 自前のサーバーは持たない。レシートの検証も端末内で完結させる。

### 5.2 ネイティブ連携のメッセージ（案）

今の`NativeBridgeMessage`（version 1）に種類を足す。

Web → Swift:

```json
{ "version": 1, "type": "storeStatus" }
{ "version": 1, "type": "storePurchasePro" }
{ "version": 1, "type": "storeRestore" }
{ "version": 1, "type": "setKeepAwake", "enabled": true }
```

Swift → Web（`CustomEvent`の`detail`）:

```json
{
  "pro": true,
  "displayPrice": "¥1,200",
  "state": "ready"
}
```

- `state`は`loading`・`ready`・`purchasing`・`pending`・`failed`のいずれか。
- `pro`は購入状態の確認中は`null`、確認後は`true`または`false`。確認中に未購入と断定して保存済み進捗を上書きしない。
- `displayPrice`は価格取得前・取得失敗時には`null`。商品取得や購入処理の状態が`failed`でも、有効な利用権限があれば`pro: true`を維持する。
- `failed`のときは、利用者に見せる`message`を添える。
- バックアップの配送と同じく、Swiftは`webReady`を受け取った後に最新の購入状態を1回送り、以降は変化があったときに送る。

### 5.3 Web（共通コア）側の境界

- 編み進めモードの盤面とUIは`packages/editor-core`に置く。`BoardCanvas`が共通なので、表示専用の`knit`モードとハイライトの描画もここに足す。
- `EditorView`に省略可能な`knitting`プロパティを足し、iOS版だけが渡す。Web版は渡さないので「編む」ボタンが出ない。
  - 渡すもの：購入済みかどうか、無料で送れる段数、購入案内を開く処理、画面消灯の切り替え。
- 購入状態はiOS版の`ios/Web/src/nativeBridge.ts`がSwiftから受け取り、`ios/Web/src/App.tsx`が`EditorView`へ渡す。
- 共通コードは公開しているWeb版のJSにも含まれる。課金を本当に守っているのはStoreKitの判定なので、それで問題ない。

### 5.4 購入画面と復元の導線

- **§3.8の開始前の案内を必ず用意する。** 11段目への操作は、既に説明した無料範囲の再案内と購入のきっかけであり、初めて課金を知らせる場面にはしない。
- 無料範囲外への操作時や、開始前の案内から「Proの購入・復元」を選んだとき、アプリ内ダイアログ（`AppDialog`）で購入案内を出す。
  - 中身：そのバージョンで使えるPro機能、全段利用が買い切りで定期料金なしであること、`displayPrice`、「購入」「購入を復元」「閉じる」。未実装の自動バックアップは列挙しない。
- 購入案内を閉じる、購入をキャンセルする、購入が失敗・完了待ちになる場合、要求した段へ移動せず、直前の試用段に留まる。無料機能は引き続き使える。
- 「購入を復元」は審査上も必要。購入案内のほかに、編み図パネルの下部にも「Pro（購入・復元）」として常に置く。
- 購入・復元による権限確認後はトーストで知らせ、同じ文書・モードで待っている場合に限り、案内を開くきっかけになった段へ進む。常に11段目へ進める処理にせず、指定段への移動や保存済み進捗からの再開も扱う。

## 8. 段階

1. **v1.0（確定）：** 今の仕様のまま、無料版のみを公開する（`TODO.md`のM6）。Proの実装を待たない。
2. **v1.1の公開前：** 少人数の実際に編む利用者へ、TestFlight等で編み進めモードを試してもらう。自作図案での再開、10段制限の開始前の理解、指定段への移動、1,200円の価値を確認する。購入意向だけを売上の証明にはしない。
3. **v1.1以降：** 編み進めモード、指定段への移動、StoreKit 2による購入・復元、開始前の説明付きの1〜10段の無料体験を追加する。発売時に使える機能に対して、買い切り1,200円を初期価格案とする。
4. **第2弾（v1.2以降の候補）：** 需要・実装負担と失敗時の安全性を確認して自動バックアップを追加する。提供時期を第1弾の購入者へ約束しない。

効果の測り方:

- iOS版には分析SDKを入れない。App Store Connectの売上レポートと「App分析」で、初回ダウンロード・Proの購入実績・収益を確認する。再ダウンロードや購入の復元を新規購入と混同しない。利用状況の指標には利用者のデータ共有への同意による制約がある。
- 「同期間の購入数 ÷ ダウンロード数」は参考値で、過去にダウンロードした人の購入も含むため、新規利用者の厳密な購入率とは呼ばない。
- この方法だけでは、無料体験に到達した人数や購入画面での離脱理由は分からない。試用者の感想を併用し、売れない場合は価格だけでなく機能の価値・案内・操作性を見直す。
- Web版のGA4には手を加えない。
